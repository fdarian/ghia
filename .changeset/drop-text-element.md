A string child is a DOM text node, and `<text>` is no longer a host element. The adapters create a string as a node of type `#text` (`createElement(id, "#text")`, then `setText`, which is for `#text` only), and it goes in any element: `<div>Saved</div>`, `<span>Saved</span>`, or a run of strings and `<span>`s as one inline paragraph; in a flex or grid container a run of strings is one anonymous item. **Breaking:** `<text>` outside an `<svg>` throws on placement (`<text> is only valid inside <svg>`), like any other SVG element; inside an `<svg>` it is SVG text, unchanged. Migrate a `<text>` that was inline (inside a `<text>` or a `<span>`) to a `<span>` and any other to a `<div>`, or put the string in the parent; `findByType("text")` and tests that read the type `text` of a string node read `#text`. A host element whose content is one paragraph is now readable by a screen reader: it is a `Label` when it has no role of its own and its text is its value whatever its role, and in a container with paragraphs beside block children each paragraph is a `Label` node of its own while a screen reader is on (inside a skipped `content-visibility` subtree those paragraphs are not separate nodes, see `docs/fork/deviations.md`). An element that holds a string directly is a costly element worth a retained root, as `<text>` was. Documented in `docs/reference.md` ("Inline text", "Accessibility").
