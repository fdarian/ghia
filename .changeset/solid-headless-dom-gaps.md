DOM gaps that headless Solid libraries (Kobalte, Base UI ports) hit. `input.value`, `checked`, `indeterminate` and `textarea.value` can be assigned before the element is mounted: the write is kept, reads give it back, and the control shows it once mounted (it used to throw "needs a mounted element"). `select()`, `setSelectionRange()` and `selectionStart`, `selectionEnd` and `selectionDirection` on an unmounted Solid text control answer from a selection kept on the element instead of throwing. `getElementsByTagName` and `getElementsByClassName` on elements and `document`, and `document.getElementsByName`, return live `HTMLCollection` and `NodeList` lists (also on `document.head` before a root mounts), and `HTMLCollection` and `NodeList` are globals. Assigning `className` sets the `class` attribute.

More gaps from running Kobalte unmodified. `<label for>` written by Solid's JSX is the label's `htmlFor`, so a click on the label toggles the control it names. `input.type` and `button.type` read the `type` attribute (a host node's `tag` field is now `elementType`). `NodeFilter`, `TreeWalker` and `document.createTreeWalker(root, whatToShow, filter)` exist, with the standard's `FILTER_ACCEPT`, `FILTER_REJECT` and `FILTER_SKIP` rules (Kobalte's focus scope, `ariaHideOutside` and menus walk the tree with them); `createNodeIterator` does not. `input.placeholder` and `textarea.placeholder` reflect the `placeholder` attribute. `innerWidth`, `innerHeight` and `visualViewport.width` and `height` keep the last size they read once the last root unmounts, as a browser window does, and throw only when no root was ever mounted (floating-ui positions after a popup's root is gone). `getComputedStyle(document.body)` answers on the stand-in `<body>` of a document with no root instead of throwing a `TypeError`.
