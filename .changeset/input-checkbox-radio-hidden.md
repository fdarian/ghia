`<input type="checkbox">`, `<input type="radio">` and `<input type="hidden">` work as in HTML, so the real `@base-ui/react` Checkbox, Switch, Radio and form fields run unchanged. A checkbox and a radio are a 13 by 13 `inline-block` box with Chrome's margin and nothing painted in it, with the role, the toggled state (`mixed` when indeterminate) and a tab stop; a hidden input builds no box, takes no focus and has no accessibility node. A click, Space, `element.click()` and a `click` an app dispatches toggle the control before the click's listeners run, put it back when one cancels the click, and otherwise fire `input` then `change` (bubbling, not cancelable); a radio unchecks its group (same `name`, same form, or the same tree with no form), and a label toggles its control once. `onInput` is a handler prop. `checked`, `defaultChecked` (only while not dirty), `indeterminate` and `value` are properties of an `<input>` element (React and Solid refs), and a control with a `checked` prop goes back to it after the change handlers. A checked checkbox or radio is in `FormData` under its `value` (`"on"` by default), a hidden input always is, and neither blocks implicit submission. `:checked` and `:indeterminate` in `matches` and `querySelector` read the live state. Arrow keys do not move between radios, and no check mark or dot is drawn: see `docs/fork/deviations.md`.
