Cmd+C, Cmd+X, Cmd+V and Cmd+A, and a new Edit menu (Cut, Copy, Paste, Select All), run as one set of GPUI actions. Outside an `<input>` or `<textarea>` they fire the DOM `copy`, `cut` and `paste` events at the focused editing host, the element of the selection, or the active element, with a `DataTransfer` in the mode the Clipboard API gives it; a cancelled `copy` or `cut` writes exactly what the handler put in `clipboardData`, and an uncancelled `copy` writes `text/plain` and `text/html` of the node selection (a text selected by dragging is still copied as before). A `preventDefault` on the `keydown` cancels the command. Select All selects the focused editing host, or the body. In an editing host, an uncancelled Cut copies the selected range and deletes it (`beforeinput` `deleteByCut`, then `input`), and an uncancelled Paste inserts the clipboard's text (`beforeinput` `insertFromPaste` with `dataTransfer` and `targetRanges`, a `<br>` for each line break, `input`); a caret, or a selection outside a host, does nothing. `document.execCommand('copy' | 'cut' | 'selectAll')` run the same commands synchronously, `'paste'` and every other command return false, and `queryCommandSupported` and `queryCommandEnabled` answer for them. `TestRenderer.simulateMenuAction(name)` chooses an Edit menu item. `<input>` and `<textarea>` fire no clipboard events: `docs/fork/deviations.md`.
