# Stylesheets

How CSS rules reach an element: `<style>` elements and constructed sheets, the rule parser, the rule index, matching, the cascade at the level of declarations, and what a change to the tree or a sheet marks to match again. The behaviour an app author sees is in [reference](../reference.md#stylesheets), the differences from CSS in [deviations](deviations.md#stylesheets).

The code is `packages/native/src/css/sheet/` (parse, match, cascade, invalidate; `tree.rs` is the retained tree's side) and `packages/native/js/css/` (the CSSOM). `renderer.rs` and `host.ts` only call into them. `retained_tree.rs` calls into them and also holds what needs its private state: the accessors of an element's per-sheet data (`css`, `set_matched`, `set_css_atoms`, behind `ElementExtras`), the style table's `InternedStyle` and the payload it keeps of each style (`raw_of`, which the cascade reads an element's own declarations from), and the restyle that merges a matched set into an element's effective style (`apply_matched`, `refresh_effective_style`). None of it moved out, because each needs a private field of `RetainedElement` or `StyleTable`.

## The shape

Ghia has one way to style an element, a JSON object of declarations (`StyleTable::intern`, the style prop). A sheet does not add a second one: a rule's declarations are turned into the same JSON text, merged with the element's own text, and interned as one style. The cascade is therefore a merge of declaration lists, and everything that makes a style prop work (lenient parsing of a bad value, `var()` held until the build, shorthands covering longhands, retention, transitions) works for a sheet with no code of its own.

```
sheet text ──parse──> rules (selectors + normal/important declarations + layer + order)
                          │
                    validate declarations, index by rightmost compound
                          │
element (tag, id, classes, attributes) ──match──> MatchedRules (interned)
                          │
MatchedRules + own style declarations ──merge──> JSON text ──StyleTable::intern──> Arc<StyleDesc>
                          │
                    RetainedElement::style (what the build, retention and getComputedStyle read)
```

No sheet at all costs one flag read per hook, and nothing else on the native side: every hook of the tree returns at `StyleSheets::enabled`, which is false until a `<style>` element or a constructed sheet exists and false again once the last is gone (`wind_down_sheets` frees the interned names, the index, the matched-set table, the `[style]` texts, the cascade cache and every element's per-sheet data). Measured (`profile-stylesheet-cost`, N=5000, release addon, medians of three runs, batch noise about 12 Minstr): items with a class and two `data-*` attributes and no sheet (`attrs`) mount in 146 Minstr of batch work (native 14.7) against 125 for the same items with none (`inline`, native 14.6), and a class or data toggle is 1.4 Minstr in both. The 21 Minstr is the JS side holding the props, which the DOM members need anyway; sending is skipped (the same run with Solid computing and recording the attributes first measured 147, so that skip is inside the noise).

## Parsing a sheet

`parser.rs` reads a token list (`tokenizer.rs`, a small CSS tokenizer; there is no `cssparser` crate in the lockfile) into a `StyleSheet`: a list of `Rule`, each with its selector list (every selector with its specificity), its normal and `!important` declarations, its `@layer` and its source `order`.

- **Declarations** keep the form the style prop has: the property name from kebab to camelCase (`--x` verbatim, `-webkit-user-select` to `WebkitUserSelect`), the value as CSS text with comments and whitespace runs collapsed, `!important` split off. A bare number for a property in the lenient parser's `UNITLESS` list is written as a JSON number, everything else as a JSON string. A declaration without a colon or with an empty value is skipped as CSS skips it.
- **Nesting.** A rule inside a style block is parsed with the parent's selectors as its `Nesting::Parent`; `&` becomes `:is(parent list)`, and a relative selector (`.b`, `> .b`) gets an implicit `&` in front. The parent's declarations written before the nested rule are one rule, those after it another, so source order is kept.
- **Layers** (`layers.rs`). `@layer a, b;`, `@layer a { }` and `@layer { }` create nodes in a tree owned by the document, not the sheet: a name is declared where it is first mentioned, in any sheet. `Layers::order()` gives each node a rank so that the sublayers of `a` rank below `a`'s own styles and all of `a` below a later sibling; unlayered styles rank above every layer. That is why every sheet is parsed again when one changes: ranks depend on every sheet's first mentions.
- **What is skipped.** Any other at-rule is skipped with its block and recorded in `StyleSheet::unsupported`, which `StyleSheets::load` logs once each, for the first 1024 distinct rules (CSS-in-JS writes a new `.css-xxx:hover` per component); past that one summary warning says further skipped rules are not logged, until the sheets are gone. An invalid selector list drops its rule.

### Selectors

`selector_parse.rs` and `selector.rs`. A `ComplexSelector` is compounds joined by combinators, stored with the subject first (`compounds[0]`, matched right to left). Simple selectors are type, universal, class, id, attribute (seven operators, `i` and `s`), `:is()`, `:where()`, `:not()`, `:root`, `:host` and the pseudo-element marker. Specificity follows Selectors 4 (`:is` and `:not` take their most specific argument, `:where` none; a nested `&` takes the parent's `:is`). A selector list is all or nothing, except inside `:is()` and `:where()`, which skip an invalid member; `:not()` is not forgiving.

### Atoms

`atoms.rs`. Tags, ids, class names and attribute names are interned to a `u32` once per document, so matching compares integers. The parser keeps classes and ids as written, and interns an attribute name (`AttrName`) and a type name (`TypeName`) twice: lower-cased, for an HTML element, and as written, for an SVG one (`linearGradient` matches `<linearGradient>` and `lineargradient` does not; the tag index holds a type under both names). Every element's `ElementCss` holds its id and class atoms while sheets exist, and only for names a sheet mentions: a class or id no sheet names cannot match a selector, so `Atoms::get` finds nothing for it and the element stores nothing (an element with no named class or id has no `ElementCss`), which keeps the interner the size of the sheets and not of every name the app ever used. The atoms are computed for all existing elements at the first flush after a sheet appears and again after a sheet load that added names (`atoms_fresh`, `reload_sheets` compares the interner's size), and kept current by the hooks in between. A name that leaves the sheets stays interned until the last sheet goes, when `wind_down_sheets` starts a new interner.

### Validation

`validate.rs`. The cascade merges declarations before any style is parsed, so a declaration that cannot parse must be removed first, or `right: bogus !important` would erase an inline `right`. `Validator::filter` judges each declaration once, when its sheet is loaded, by the check `StyleTable::intern` runs on a style: it must parse to a style that is not empty, keep every value of it past the check a state style gets when it layers over its base (`without_invalid_values`: a transform, a filter, a background, a border shorthand that does not parse), and for `color`, `outlineColor` and `textDecorationColor` resolve as a colour. Custom properties, `var()` values and CSS-wide keywords are accepted without a check (the first two are only known at build time, the keyword is the cascade's own). A key the style does not know parses to the empty style and is dropped, as CSS drops an unknown property. A property's initial value written as a keyword the parser has no form for (`z-index: auto`, `max-width: none`, `max-height: none`, `gap`, `row-gap` and `column-gap: normal`, `line-clamp: none`; `UNREPRESENTABLE` in `initial.rs`) is accepted as `initial`, in a sheet and in an inline style. Verdicts are cached by the declaration's JSON text, bounded at 4096. A rule left with no declaration is dropped.

## The rule index and matching

`index.rs`. `RuleIndex::build` numbers the rules in cascade source order (sheet by sheet) and puts each selector of each rule in one bucket, chosen by the most selective thing its subject compound requires: an id, else a class, else an attribute name, else a tag, else the universal list. A rule whose selectors are all pseudo-element selectors is left out.

`RuleIndex::matching(element)` visits the buckets of the element's id, its classes, every attribute name some selector reads (and the element has), its tag, and the universal list, runs the full right-to-left match (`matching.rs`, over the `ElementView` trait; `view.rs` is the retained tree's implementation) on each candidate, and sorts the matches by (layer rank, specificity, source number). A rule counts once, at the specificity of the most specific of its selectors that matched.

`TreeView::attr` reads an attribute from the element's attribute store (`attributes.rs`, set by wire op 13) and from nowhere else: the store holds exactly the element's DOM attributes, named as the DOM names them. An HTML element stores a name lower-cased and a selector's name is compared lower-cased (`[tabIndex]` reads `tabindex`); an SVG element (`svg`, a tag only an `<svg>` holds, and `text`, see `svg_tree::is_svg_tag`) stores a name as written and a selector's name is compared as written (`svg[viewBox]` matches, `svg[viewbox]` does not). A prop that is not an attribute reaches native as a custom prop only and no selector sees it. `style` is special: the text is synthesized from the element's own style declarations (`kebab-key: value;`, as the DOM's `cssText` has them: a `null` or empty value is no declaration, and a number on a property that is not unitless and not zero has `px`, so `[style*="width: 10px"]` matches `{ width: 10 }`; cached per own-style `Arc`, `StyleSheets::style_text`, and handed to the matcher as a shared `AttrValue`), so `[style*="--dnd-scale"]` works. The attribute operators compare in place (ASCII case-insensitively for the `i` flag), so a check allocates nothing. The cached texts are released at the end of every flush for own styles no element holds, and cleared at wind-down. A `#text` node is not matchable.

### Matched sets are interned

`cascade.rs`. The result of matching is a `MatchedRules`: the rule numbers in the order their normal declarations apply and the rules with important declarations in the order those apply (layers compare the other way round there: the first layer wins, unlayered rules lose). Equal match lists are interned by a table of weak references (`MatchedInterner`, pruned when it doubles), so a thousand `.item` elements hold one `Arc` and are compared and cached by its pointer.

## The cascade

`cascade::merge` works on declarations as the style prop's JSON would hold them:

1. the normal declarations of each matched rule, in `matched.normal` order;
2. the element's own declarations, in written order (`StyleTable::raw_of` gives the own style's JSON, read back with the lenient parser's `Declarations`), less the ones that are no inline value: `null`, `""` (React DOM's "no value") and a value the validator rejects, so `{color: "bogus"}` does not take back a sheet's `color`. A nested object (a state style) and a custom property pass;
3. the important declarations of each rule in `matched.important` order;
4. the element's own declarations that were written `!important` (`inline_important.rs` strips the suffix of a string value before `StyleTable::intern` parses a payload, so with no sheet it is the plain value; the table keeps the payload as it came and `cascaded` splits the declarations that had it off, in written order). An inline `!important` beats an author one, as in CSS. React hides a Suspense child with it (`display: none !important`, as React DOM does).

A later declaration of a key removes the earlier one and is appended, which is where `css/covers.rs` reads "written order" from when the merged text is interned: a shorthand drops the longhands before it, a longhand after it stays. A CSS-wide keyword (`apply`) removes the key and the longhands it covers from what came before. When an earlier shorthand in the list still covers one of those longhands (`inset: 0` and then `right: unset`), the longhand's initial value (`sheet/initial.rs`) is appended after it, which `css/covers.rs` ranks above the shorthand; a longhand with no entry there only has the removal. The merged text goes through `StyleTable::intern` and the universal layer (`<UniversalStyle>`) and the user agent style of the tag ([layout.md](layout.md#html-tags)) are put under the result exactly as for an element with no sheet match (`refresh_effective_style`), so the order from the bottom is: user agent style, `*`, rule, inline, `!important` rule, `!important` inline value. A merge whose text does not parse leaves the element its own style and is logged.

### The cascade cache

`CascadeCache`, `StyleTable::cascaded`: keyed by (matched `Arc` pointer, own style `Arc` pointer) and holding a `Weak` to each, which keeps the allocation reserved, so addresses cannot be reused while an entry lives, and no entry pins the own style or the rules. N elements that match the same rules and share an own style cost one merge (`cascadesComputed` counts the misses). The cache is cleared when the sheets change. `release_unused` (run by `StyleTable::sweep`) counts, per style, the entries that hold it (as their style or as their own style: a merge that adds nothing to the own style is the own style itself, and entries whose merges coincide share one) and drops an entry when the style has no holder but those entries and the style table, so the table can sweep it. An entry is also dropped once no element holds its own style (the style table and the entries whose merge is that style do not count) or its rules, since only an element can look it up: many own styles that merge to one style (an inline `left` under a rule's `left: 0 !important`, animated per frame) would otherwise stay pinned by the entry whose merged style is in use. It repeats while an entry dropped lets go of another's style. No sheet matches an element: its effective style is the own style, the same `Arc`, and the cache is not asked.

## What a change marks

`invalidation.rs`. When the index is built, `Invalidation::read` walks every selector and records, per feature, where a change of that feature can alter a match, as a `Reach`: nine bits, `{the element, its next sibling, all following siblings} x {itself, its children, everything below}`.

A feature (a class atom, an id atom, an attribute name, and `style`) sits in some compound of a selector. The elements the selector styles are reached from the compound by the combinators to its right: a descendant or child combinator reaches the subtree (children, or everything below), `+` the next sibling, `~` the following siblings, and a sibling combinator followed by a descendant one the subtrees of those siblings. A feature in the subject compound reaches just the element. A `&` list that nested rules share is read once per what the chain of combinators leading to it does to each of the nine places (`Reach::image`), not once per chain, so `& > &, & + &` nested to the depth limit is read in a bounded number of steps. Features inside `:is`, `:where` and `:not` take the position of the compound that holds them, and an argument with combinators of its own is read through them and then through the rest of the selector. `structure` is the reach of an element appearing or disappearing among its siblings (non-empty only when a sibling combinator exists). A feature no selector names has no entry: a change to it marks nothing.

The tree's hooks (`tree.rs`) collect `(element, Reach)` marks:

| Change | Mark |
|---|---|
| class attribute (symmetric difference of the atom sets, plus the reach of `[class]`), `id`, any other attribute | the reach of what changed |
| own style change | the reach of `[style]`, which is empty unless a selector reads it |
| element inserted or moved | the element and its subtree, plus `structure` |
| element about to be removed | the next matchable sibling, with `structure`, since what follows matches without it |
| text of a `<style>` element, `<style>` inserted, removed or moved, root changed, constructed sheet changed or the adopted list changed | the sources are dirty: every element matches again |

### The flush

`flush_styles`, called once at the end of `apply_batch_to_tree`, after the last op, so a batch matches each element once however many ops touched it:

1. If the sources are dirty, `reload_sheets`: collect the texts of the connected `<style>` elements in tree order (`tree_path` compares positions among siblings), then the adopted constructed sheets in list order. If they equal the texts the index was built from nothing happens; otherwise `StyleSheets::load` parses all of them again with one `Atoms` and one `Layers`, validates, builds the index, clears the interner and the cascade cache and marks everything.
2. If the atoms are not fresh, compute them for every element and mark everything.
3. Expand the marks into the set of elements to match (`restyle_set`, `Expansion`): each reach becomes the element, its children or its subtree, and the next or following siblings, each element once and each subtree walked once. The marks that reach siblings are grouped by parent (`expand_siblings`): one map of the parent's children gives their positions, and the following siblings are walked once from the first mark with the reaches of the marks before each folded together, so mounting n siblings under a sibling combinator is linear. A mark of everything is the document in tree order plus the elements outside it (which match nothing).
4. Match each (`elementsRematched` counts them; `SiblingPositions` in `view.rs` gives `prev_sibling` the element's index among its siblings in O(1), mapping a parent's children the second time it is asked, so `+` and `~` do not scan the siblings per step; the same pass remembers, per parent and per `~` in a selector, the first earlier sibling that satisfies the rest of the selector, so `.x ~ .item` over n siblings is n steps whether or not a `.x` exists), intern the result, and compare it to the element's current `matched` by pointer.
5. `apply_matched` for the ones that changed: store `matched`, `refresh_effective_style`, `settle_style_change`. That is the path `set_style` takes, so retention, the transition source style and the paragraph grouping see an ordinary style change. An element created in the batch has no transition source style: what the batch assigns it before the cascade lands (its own style, the user agent style, then the sheets' result) is not a style anything was drawn with, and CSS never transitions the first style of an element (`RetainedTree::finish_batch` ends the batch). `set_style` compares the interned style by pointer, not the parsed style, which has dropped `!important`: `{ color: "red" }` to `{ color: "red !important" }` restyles.
6. Drop the `[style]` texts no element holds (the cascade entries go at the style table's next sweep), and wind down if no sheet is left.

Whether a moved or removed element holds a `<style>` element (`contains_style_element`) is answered by walking its subtree when that is small next to the number of `<style>` elements, and from the `<style>` elements up to the root when it is not.

An element that is not in the document, or is not matchable, matches nothing: removing a `<style>` element restores every element it styled.

## Sheet sources

- **`<style>` elements.** An element of type `style` registers in `style_elements` when created. Its sheet text is the concatenation of its `#text` children. It takes part while connected to the root, in tree order. `display` reads `none` for it (`RetainedElement::display`), so layout skips it and the build never draws it. Solid lists `style` as an element type (`isElementType`) and React's host config forwards any type and a string child becomes a `#text` node as anywhere.
- **Constructed sheets**, wire ops 14 and 15 (`batch/wire.rs`, `BatchOp::SetStyleSheet`, `SetAdoptedStyleSheets`). `constructed` maps a sheet id to its text; `adopted` is the ordered list that applies, after the `<style>` elements. A sheet in the map and not in the list does nothing. Sheet ids are a namespace of their own.

## Attributes and wire ops 13 to 15

Op 13 `setAttribute(id, name, value | null)` stores into the element's attribute store; the JS adapters forward every prop that `element.attributes` lists (`attributesOfProps` in `js/dom/attribute-names.ts`: not `children`, `key`, `ref` or `style`, and no handler or object), named by `attributeNameOf(prop, svg)` and valued by `attributeText`, the two functions `getAttribute`, `getAttributeNames` and `MutationRecord.attributeName` use, so the native store and the DOM agree by construction (see [reference](../reference.md#listeners-and-dom-members-on-an-element)). A prop native also reads (`id`, `tabIndex`, `width` on a canvas) goes as an attribute and as a custom prop; `class` and `data-*` go as op 13 alone, never also as a custom prop, so an element of any type pays one op for each. Nothing in native reads an attribute but the cascade, so an app with no sheet sends none (see below).

### The attribute gate

`js/css/attribute-gate.ts`. Every attribute send of an adapter goes through its mutation queue's `setAttribute`, which drops it while the gate of the queue's renderer is closed; the JS side (`getAttribute`, `dataset`, props) reads JS state and does not notice. A gate opens, for good, the first time a sheet can apply to that renderer: a `<style>` element is created (`createElement` of type `style`), a constructed sheet's text is sent (`setStyleSheet`) or the adopted list becomes non-empty (`setAdoptedStyleSheets`; a renderer created while sheets are adopted opens when its queue registers). Opening it makes every queue of the renderer send, first, the attributes of the elements it already holds (`MutationQueue.backfillAttributes`), read from the adapter's own registry of mounted elements through `ElementSource` (`setElementSource`: Solid's `HostRoot.elements`, React's `Container.instances`) with the same `attributesOfProps` the live sends use. React skips its own sends while the gate is closed (`MutationRenderer.forwardsAttributes`), since the backfill reads its instances' current props; Solid skips them too, and the backfill fills its per-node record of what it sent (`ElementSource.rememberAttributes`, which the queue calls with the attributes it just sent), so a later removal or an unchanged write is judged against what native holds. The backfill is queued ahead of the sheet op, except for a `<style>` element, where it follows the element's own `createElement` (Solid lists a node as mounted before its element is queued). Native applies a batch's ops in order and restyles once at the end, so no element is matched before it has its attributes. Once open the gate stays open: closing it would need native to forget the attributes. The test renderer's `getAttribute` reads native, so a test that reads it mounts a `<style>` first. Ops 14 and 15 carry the constructed sheets. All three are in the binary batch (`js/wire.ts`, `WIRE_OPCODE`) and decoded by `wire-testing.ts` for the tests. Layout of each is in [reference](../reference.md#wire-format).

## The JS side

`packages/native/js/css/`, framework neutral:

- `rules.ts` splits sheet text into top-level rules (strings, comments, escapes, parentheses and nested braces; an at-rule ends at its block or a `;`, a style rule only at its block, as in the native parser). A `}` with nothing open starts the next rule's prelude, as in CSS Syntax and the native parser, so that one rule is dropped with its block and the rules after it stay; a constructed sheet and a `<style>` with the same text list and style the same rules. It does not interpret a rule. `CSSStyleSheet.cssRules` lists what it finds.
- `style-sheet.ts`: `CSSStyleSheet`, `CSSRule`, `CSSStyleRule`, `CSSRuleList`. Every change to the rule list calls `sheetChanged`, which sends the whole text (`sheetText()`: the rule texts joined by newlines).
- `observable-array.ts`: a `Proxy` over an array that checks every value (`convert`) and reports once per change; the mutating methods are wrapped so they are one change, not one per element they touch.
- `adopted.ts`: `document.adoptedStyleSheets`, one array for the document.
- `sheet-sync.ts`: what reaches native. Sheets are per native tree, so there is one record per renderer (not per queue): the ids of the sheets whose text it holds and the adopted list it holds. `registerSheetSink(renderer, queue)` is called by `createMutationQueue`, which is how a renderer mounted after sheets were adopted gets them. A change computes what each renderer lacks: `setStyleSheet(id, text)` for a sheet it has not seen or whose text changed, `setAdoptedStyleSheets(ids)` when the list differs from the one sent (a sheet listed twice counts at its last place, a disabled sheet is left out), and `setStyleSheet(id, null)` for a sheet that left the list. The ops go through any live queue of the renderer, so they ride in its next batch like every other op. A change to the text of a sheet native already holds does not write at once: the sheet is marked dirty (`RendererSheets.dirty`) and its queue told (`sheetsDirty`), and the queue writes one `setStyleSheet` per dirty sheet as it starts to flush (`flushDirtySheets`), so n `insertRule` calls in a tick are one op of n rules, not n ops of growing text. Adoption, enabling and removal still write at once, and the gate is open by the time a held sheet changes, so the backfill still precedes every sheet op.
