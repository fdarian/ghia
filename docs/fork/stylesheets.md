# Stylesheets

How CSS rules reach an element: `<style>` elements and constructed sheets, the rule parser, the rule index, matching, the cascade at the level of declarations, and what a change to the tree or a sheet marks to match again. The behaviour an app author sees is in [reference](../reference.md#stylesheets), the differences from CSS in [deviations](deviations.md#stylesheets).

The code is `packages/native/src/css/sheet/` (parse, match, cascade, invalidate; `tree.rs` is the retained tree's side) and `packages/native/js/css/` (the CSSOM). `renderer.rs` and `host.ts` only call into them. `retained_tree.rs` calls into them and also holds what needs its private state: the accessors of an element's per-sheet data (`css`, `set_matched`, `set_css_atoms`, behind `ElementExtras`), the style table's `InternedStyle` and the payload it keeps of each style (`raw_of`, which the cascade reads an element's own declarations from), and the restyle that merges a matched set into an element's effective style (`apply_matched`, `refresh_effective_style`). None of it moved out, because each needs a private field of `RetainedElement` or `StyleTable`.

## The shape

Ghia has one way to style an element, a JSON object of declarations (`StyleTable::intern`, the style prop). A sheet does not add a second one: a rule's declarations are turned into the same JSON text, merged with the element's own text, and interned as one style. The cascade is therefore a merge of declaration lists, and everything that makes a style prop work (lenient parsing of a bad value, `var()` held until the build, shorthands covering longhands, retention, transitions) works for a sheet with no code of its own.

```
sheet text ──parse──> rules (selectors + normal/important declarations + layer + order)
                          │
                    validate declarations, index by rightmost compound
                          │
element (tag, id, classes, attributes) ──match──> MatchedRules (interned)
                          │
MatchedRules + own style declarations ──merge──> JSON text ──StyleTable::intern──> Arc<StyleDesc>
                          │
                    RetainedElement::style (what the build, retention and getComputedStyle read)
```

With no sheet, every hook of the tree returns at `StyleSheets::enabled` (one flag read), which is false until a `<style>` element or a constructed sheet exists and false again once the last is gone (`wind_down_sheets` frees the interned names, the index, the matched-set table, the `[style]` texts, the cascade cache and every element's per-sheet data). Three costs are not behind that flag: each `StyleTable::intern` miss scans the payload for `!important` (`inline_important::strip_payload`) and records the raw text in the `raws` map, which the sweep removes with the style; each element carries an `is_svg` `OnceCell`, empty until the first attribute read, which an app with no sheet never makes; and each `createElement` inserts the id into the `fresh` set that the end of a frame's build clears for what it built (`RetainedTree::note_frame_built`, the transition-on-mount fix). Their measured cost, `profile-stylesheet-cost` in `inline` mode (the `style` prop, no sheet) at N=5000 against `main` in the same session, 7 interleaved runs each, medians: a mount is 454.8 and 456.9 Minstr end to end (two series) against main's 456.1 and 453.7, inside the noise (a run is within 3 Minstr of the median, with spikes up to 25), and native `applyBatch` is 15.3 against 14.3 Minstr, about 1 Minstr (0.2% of the mount); a class or data toggle is 306 Minstr in both (one whole frame) and the all-items update 442 against 444. Each element also holds one `markup` pointer (8 bytes, `None` until it has an attribute or sheet data). With a sheet that matches every element (`sheet` mode, a class rule of the eight declarations the `inline` look sets; same bench, N=5000, 7 interleaved rounds, medians) a mount costs 30.1 Minstr in native `applyBatch` against 16.0 for the style prop (38.1 before the shared attribute storage and style sharing), 464 against 475 end to end (the end-to-end noise is about 10, with spikes to 25 in the `inline` runs); loading the sheet over 5000 existing elements 12.0 (17.0 before), and the all-items class change 76.3 against 65.0 for the all-items style swap (82.8 before). A class or data toggle on one item is 0.04 against 0.02. What is left over the style prop is per-element work: the class attribute's op and string, the key build and lookup, and `apply_matched`. Measured (`profile-stylesheet-cost`, N=5000, release addon, medians of three runs, batch noise about 12 Minstr): items with a class and two `data-*` attributes and no sheet (`attrs`) mount in 146 Minstr of batch work (native 14.7) against 125 for the same items with none (`inline`, native 14.6), and a class or data toggle is 1.4 Minstr in both. The 21 Minstr is the JS side holding the props, which the DOM members need anyway; sending is skipped (the same run with Solid computing and recording the attributes first measured 147, so that skip is inside the noise).

## Parsing a sheet

`parser.rs` reads a token list (`tokenizer.rs`, a small CSS tokenizer; there is no `cssparser` crate in the lockfile) into a `StyleSheet`: a list of `Rule`, each with its selector list (every selector with its specificity), its normal and `!important` declarations, its `@layer`, its `@media` conditions ([Conditions](#conditions)) and its source `order`, and beside the rules the `@keyframes` and `@property` definitions ([Definitions](#definitions-keyframes-and-property)).

- **Declarations** keep the form the style prop has: the property name from kebab to camelCase (`--x` verbatim, `-webkit-user-select` to `WebkitUserSelect`), the value as CSS text with comments and whitespace runs collapsed, `!important` split off. A bare number for a property in the lenient parser's `UNITLESS` list is written as a JSON number, everything else as a JSON string. A declaration without a colon or with an empty value is skipped as CSS skips it.
- **Nesting.** A rule inside a style block is parsed with the parent's selectors as its `Nesting::Parent`; `&` becomes `:is(parent list)`, and a relative selector (`.b`, `> .b`) gets an implicit `&` in front. The parent's declarations written before the nested rule are one rule, those after it another, so source order is kept.
- **Layers** (`layers.rs`). `@layer a, b;`, `@layer a { }` and `@layer { }` create nodes in a tree owned by the document, not the sheet: a name is declared where it is first mentioned, in any sheet. `Layers::order()` gives each node a rank so that the sublayers of `a` rank below `a`'s own styles and all of `a` below a later sibling; unlayered styles rank above every layer. That is why every sheet is parsed again when one changes: ranks depend on every sheet's first mentions.
- **`@media` and `@supports`** are read where a rule can stand (the top of a sheet, an `@layer`, each other) and inside a style rule, where the block holds declarations for the rule's selectors and nested rules, flushed in source order like nested rules are. [Conditions](#conditions) says what they do.
- **`@keyframes` and `@property`** are read where a rule can stand (the top of a sheet, an `@layer`, `@media` and `@supports`), not inside a style rule. They are not rules of the index: each becomes a `Defined<T>` (the body, its layer and its conditions) in `StyleSheet::keyframes` and `StyleSheet::properties`. [Definitions](#definitions-keyframes-and-property) says what the document does with them.
- **What is skipped.** Any other at-rule is skipped with its block and recorded in `StyleSheet::unsupported`, which `StyleSheets::load` logs once each, for the first 1024 distinct rules (CSS-in-JS writes a new `.css-xxx:hover` per component); past that one summary warning says further skipped rules are not logged, until the sheets are gone. An invalid selector list drops its rule.

### Selectors

`selector_parse.rs` and `selector.rs`. A `ComplexSelector` is compounds joined by combinators, stored with the subject first (`compounds[0]`, matched right to left). Simple selectors are type, universal, class, id, attribute (seven operators, `i` and `s`), `:is()`, `:where()`, `:not()`, `:root`, `:host`, the five state pseudo-classes, the tree-state pseudo-classes (`Simple::TreeState`, below), the structural pseudo-classes (`Simple::Position`, below), `:has()` (`Simple::Has`, below), and the pseudo-element marker. Specificity follows Selectors 4 (`:is` and `:not` take their most specific argument, `:where` none; a nested `&` takes the parent's `:is`; every pseudo-class is (0,1,0)). A selector list is all or nothing, except inside `:is()` and `:where()`, which skip an invalid member; `:not()` is not forgiving.

**Structural pseudo-classes.** `:first-child`, `:last-child`, `:only-child`, `:nth-child()`, `:nth-last-child()`, `:first-of-type`, `:last-of-type`, `:only-of-type`, `:nth-of-type()`, `:nth-last-of-type()` and `:empty` parse into one `Simple::Position(Position)` (`nth.rs`: `Nth { of_type, from_end, an_b }`, where `:first-child` is `0n+1`, `Only { of_type }` and `Empty`), each (0,1,0), in any compound and inside `:is()`, `:where()` and `:not()`. `An+B` is read from the tokens by CSS Syntax 3 section 6 (`AnPlusB::parse`: `odd`, `even`, `n`, `-n+3`, `2n + 1`, `+5`, `2n- 1`, any case; `2 n`, `+ 2n`, `n+`, a float and `2n+-1` are not one). `of S` is not read: the argument stops being an `An+B`, so the selector is invalid. The matcher asks `ElementView::child_index(of_type, from_end)` (1-based, over the element children only: a `#text` node is not counted, an element with no parent is alone, and an element the parent does not list matches none) and `is_empty` (no element child and no child text with text in it; whitespace is text). `TreeView` answers `child_index` from `SiblingPositions::slot`: the first time a flush asks about a parent the children are walked for that element, the second time every child is numbered into a map (from the start and the end, over all elements and over those of the same type, which compares as `Tag` matching does: an HTML type without case, an SVG type as written; an element counts as SVG by its tag name, so an `a` inside an `<svg>` is an HTML `a`, a deviation listed in deviations.md), so a thousand rows with `:nth-child(odd)` are one numbering.

**`:has()`.** `has.rs`. `:has(<relative selector list>)` parses into `Simple::Has(HasArguments)`: each argument is a `RelativeSelector`, a leading combinator (`>`, `+`, `~`, or none, which is descendant) and a `ComplexSelector` stored as any other. It is not forgiving (one invalid argument invalidates the selector), it does not nest (a `:has()` in a `:has()` argument, also through `:is()` or `:not()`, is invalid), and a pointer or focus state (`:hover`, `:active`, `:focus`, `:focus-visible`, `:focus-within`) is invalid anywhere inside it, also inside a `:is()` or `:where()` there (which does not forgive it: the whole selector is invalid) and one that `&` brings in (`.item:hover { .list:has(> &) { } }` is invalid, since the parent holds a state; a parent with none is fine), since a state compiles into a style block of the subject (`states.rs`) and an element inside an argument has none; a pseudo-element is invalid too. It may stand in any compound and inside `:is()`, `:where()` and `:not()`, counts as its most specific argument, and is never self-contained, so style sharing does not reuse a match across elements that hold different things below them. The matcher goes down from the anchor and never up: for each argument it tries what the leading combinator leads to (the children, the subtree, the next sibling or the siblings after), matches the leftmost compound there, and goes on to the next with the argument's own combinators (`ElementView::children` and `next_sibling`). A subject is found by the same walk wherever the anchor is among the compounds of the selector, so `.card:has(.err) .title` asks `.card:has(.err)` of each ancestor of a `.title`. The answer for an anchor and an argument list is remembered for the flush (`ElementView::remembered_has`, keyed by the element and the list's address, in `SiblingPositions`), so a card with a hundred titles is searched once. A rule is filed under the key of its subject, so `.btn:has(> svg)` sits in the `.btn` bucket; one whose subject is only a `:has()` is in the universal list.

### Atoms

`atoms.rs`. Tags, ids, class names and attribute names are interned to a `u32` once per document, so matching compares integers. The parser keeps classes and ids as written, and interns an attribute name (`AttrName`) and a type name (`TypeName`) twice: lower-cased, for an HTML element, and as written, for an SVG one (`linearGradient` matches `<linearGradient>` and `lineargradient` does not; the tag index holds a type under both names). Every element's `ElementCss` holds its id and class atoms while sheets exist, and only for names a sheet mentions: a class or id no sheet names cannot match a selector, so `Atoms::get` finds nothing for it and the element stores nothing (an element with no named class or id has no `ElementCss`), which keeps the interner the size of the sheets and not of every name the app ever used. The atoms are computed for all existing elements at the first flush after a sheet appears and again after a sheet load that added names (`atoms_fresh`, `reload_sheets` compares the interner's size), and kept current by the hooks in between. A name that leaves the sheets stays interned until the last sheet goes, when `wind_down_sheets` starts a new interner.

### Validation

`validate.rs`. The cascade merges declarations before any style is parsed, so a declaration that cannot parse must be removed first, or `right: bogus !important` would erase an inline `right`. `Validator::filter` judges each declaration once, when its sheet is loaded, by the check `StyleTable::intern` runs on a style: it must parse to a style that is not empty, keep every value of it past the check a state style gets when it layers over its base (`without_invalid_values`: a transform, a filter, a background, a border shorthand that does not parse), and for `color`, `outlineColor` and `textDecorationColor` resolve as a colour. Custom properties, `var()` values and CSS-wide keywords are accepted without a check (the first two are only known at build time, the keyword is the cascade's own). A key the style does not know parses to the empty style and is dropped, as CSS drops an unknown property. A property's initial value written as a keyword the parser has no form for (`z-index: auto`, `max-width: none`, `max-height: none`, `gap`, `row-gap` and `column-gap: normal`, `line-clamp: none`; `UNREPRESENTABLE` in `initial.rs`) is accepted as `initial`, in a sheet and in an inline style. Verdicts are cached by the declaration's JSON text, bounded at 4096. A rule left with no declaration is dropped.

### State pseudo-classes

`states.rs`. `:hover`, `:active`, `:focus`, `:focus-visible` and `:focus-within` are not tree state (the pointer is `GpuixView.pointer`, the focus `GpuixView.focus`, neither in the `RetainedTree`), and an element already styles them through the `hover`, `active`, `focus`, `focusVisible` and `focusWithin` blocks of its style, which the build folds (`pointer_states_of`, `FocusStyles::folded`) with their own invalidation (`HoverChange` and `hover_paint.rs` for the paint-only path, `pointer_bits` and `focus_bits` for retention). A sheet therefore does not match live state: it compiles into those blocks, and nothing about hover or focus is invalidated by the sheets.

- **Parse.** `Simple::State(State)` is one of the five. The parser works out `ComplexSelector::condition` from the finished compounds (`states::condition_of`): the state of the subject compound, directly or through `:is()` and `:where()` arguments that all have the same one. A state anywhere else (a compound that is not the subject, which includes the implicit `&` of a nested rule whose parent is under a state, two different states in one compound, inside `:not()`, a mixed `:is()`) makes the selector invalid, so a rule drops, or an `:is()` and `:where()` argument is skipped, with the rest of the list kept.
- **Match.** `simple_matches` reads `Simple::State` as true. The match is the selector's without the state, which makes it self-contained for style sharing and independent of where the pointer is.
- **Matched sets.** `RuleIndex::matching` keys what it finds by (rule, condition) at the specificity of the most specific selector of that rule under that condition, so `.a, .b:hover` is one entry with no condition and one under `:hover`. `MatchedRules` holds `Applies { rule, condition }` and is interned with the condition in the key.
- **The cascade** (`states::merge`, run instead of the plain merge only when a matched rule has a condition or the element has a state block of its own, so an element that matches a rule and has no state block, under a sheet with no state selector, pays what it did; an element with an inline state block that matches any rule goes through it, once per distinct (matched rules, inline style) pair, since the result is cached). The same sequence as above (rules in order, the inline style, important rules, important inline) gets a position per step. An unconditional declaration is merged as before. A conditional one is kept with its state and position, and survives unless an unconditional declaration of the same property, or of a shorthand that covers it, has a higher position: the first of the property from the top that has no condition is the base value and shadows what is under it, which is "from the highest down, collecting conditional values until the first unconditional one". An inline block of any of the five states is read as conditional declarations at the inline position (an inline `hover` block and `.a:hover` rules merge property by property, the inline one winning), whether or not a rule is under that state, so the cascade of an element with a sheet match does not change when a rule starts to target a state its inline style already has. A conditional declaration that survives and overlaps (`covers::overlaps`) a property an unconditional declaration above it sets (`.btn:hover { background: blue }` over an inline `backgroundColor: red`, or `.a:hover { border-color: blue }` over an inline `borderTop`, which a side shorthand and an all-sides value split between them) is followed in its block by the base value of that property, so it stays as CSS has it, red while hovered. A declaration the one above covers outright is shadowed instead. An inline `!important` beats the element's own inline state block of the property whether or not a sheet matches the element: with no match `StyleTable::intern` runs this same merge for a payload that holds both (`inline_important::strip_payload`, only for a payload that mentions `important`). What survives is written as the block of its state, appended to the merged object in the order the states fold. The result goes to `StyleTable::intern` like any other text, so the element's `StyleDesc` is the one an inline `hover` writes, and every later stage (the fold, `differs_only_in_paint`, `hover_paint`, retention) classifies it as it does that.
- **Where two states disagree.** The blocks fold in a fixed order (hover, active, then focus, focusWithin, focusVisible), so a property two states set goes to the later state when both apply, even when the cascade would pick the other. `warn_when_fold_disagrees` logs it once for each property and pair of states for the life of the sheets (`LoggedFolds`, kept across reloads and cleared by `wind_down`, capped like the skipped rules), and not when the two values are equal.
- **Tree-state pseudo-classes.** `:popover-open`, `:disabled`, `:enabled`, `:checked`, `:indeterminate`, `:required`, `:optional`, `:read-only`, `:read-write`, `:any-link` and `:link` (the same state: nothing is visited) parse into `Simple::TreeState(TreeState)` (`tree_states.rs`), each (0,1,0), in any compound and inside `:is()`, `:where()` and `:not()`. The matcher asks `ElementView::tree_state`, which `TreeView` answers from what native already holds, with no state of its own:
  - `:popover-open`: `html::popover::is_open`.
  - `:disabled` and `:enabled`: `RetainedElement::control_disabled`, the rule the inline `disabled` and `enabled` blocks use, so a `button`, `input`, `select` or `textarea` and a `div` that says `formControl` are controls, and every other element matches neither (a `fieldset`, an `optgroup` and an `option` included, where Chrome matches a `<fieldset disabled>` and an `option` with `:disabled`).
  - `:checked` (a checked checkbox or radio) and `:indeterminate` (an indeterminate checkbox): the live checkedness in `Choices` (`is_checked`, `is_indeterminate`), which a click, a script and a prop write. A radio is never `:indeterminate`, where Chrome matches a radio whose group has no checked radio.
  - `:required` and `:optional`: a `select`, a `textarea` and an `input` whose `type` is not `hidden`, `range`, `color`, `submit`, `reset`, `button` or `image`, with and without the `required` prop; no other element matches either.
  - `:read-write`: a `textarea`, or an `input` whose `type` is edited as text (a missing or unknown one too, not `checkbox`, `radio`, `range`, `hidden`, `color`, `file`, `button`, `submit`, `reset`, `image`), that is neither `readOnly` nor disabled. `:read-only` is every other element. An element that is editable (`contenteditable`, inherited from the nearest ancestor that has one) is `:read-write` instead, except a text control, which is read-write by its own state whatever it sits in.
  - `:any-link`: an `a` or `area` with an `href`.

  `Invalidation::tree_states` (`TreeStateReach`) is the reach of the selectors that read each state, empty for a state no selector names. A selector with one is not self-contained, so an element it can match is matched in full, and one that holds nothing else falls to the full reload path as `:popover-open` always did. Two hooks mark: `set_custom_prop` calls `sheets_tree_state_changed(id, TreeStates)` with `TreeStates::changed_by_prop(key)` (`disabled`, `formControl`, `required`, `readOnly`, `href`, `type`; `popover` and `popoverOpen` are `:popover-open`), and every place a checkedness or an indeterminate flag changes in `input_choice.rs` (`choice_state_changed`: a click, `checked`, `defaultChecked`, `indeterminate`, a radio unchecking its group, a canceled click, a controlled restore) calls it for `:checked` and `:indeterminate`, so a radio checked marks itself and the one it unchecked.

## Conditions

`conditions.rs`, `css/media_query.rs`, `supports.rs`.

**`@media`.** A rule carries the media queries of every `@media` around it (`Rule::conditions`, an `Arc<Conditions>`: the lists outermost first, all of which have to match). `css/media_query.rs` parses and evaluates one list: the grammar and features of `js/media-query.ts` (the evaluator behind `matchMedia`, which keeps its own) plus `resolution`, with the same rule for what it does not know: an item that does not parse or names an unknown feature or value is `not all`, and the other items of its comma list still count. `MediaEnvironment` is what a query reads: the viewport in CSS pixels, the scale factor, the colour scheme, reduced motion, increased contrast, forced colors. The serializer is not ported; a list keeps its source text with the whitespace collapsed, which is what two lists are the same query by.

A rule whose conditions do not hold is not indexed: `StyleSheets::load` drops it before `RuleIndex::build` (`conditions::holds`), so matching, the matched sets, the cascade cache, style sharing and the invalidation tables never see it, and an index built with the window as it is has no rule for what does not apply. The parse cache is untouched: a top-level rule parses to the same `ParsedRule` whatever the window is (its rules carry their conditions in `DocRule`), and `ParsedRule::active_len(environment)` is how many of them the index holds, which `Reload::between` needs to number the rules of a shared unit. Before the window has reported an environment (`StyleSheets::media` is `None`) no condition holds.

**What the window gives it.** The environment lives on `StyleSheets`, the document's (`media`), and `RetainedTree::set_media_environment` is the one way in. `GpuixView` reads it from the window and calls `media::sync_sheets`: when the window is made (`observe_viewport`), on every bounds change, on every appearance change, and, on macOS, when the OS accessibility options change (`observe_media_features`, its own `NSWorkspace` observer, so it does not depend on a `mediaChange` listener; the `mediaChange` event is emitted as before, only when JS asked). The test renderer starts with no OS preference and `setMediaFeatures` feeds the same path.

**What a flip reloads.** `StyleSheets` keeps each distinct query of the loaded rules with the answer the index was built on (`Watched`). `set_media_environment` evaluates each against the new environment, and when none answers differently it returns at once: a window drag that crosses no breakpoint costs one evaluation of each distinct query, no reload, no match. When one flips it sets `media_flipped` and `sources_dirty`, and `take_dirty_restyled` runs the flush: `reload_sheets` loads the same texts again (every unit comes from the parse cache; nothing is parsed) and, since the numbering of the rules says nothing about the new index, takes the full path: the interner and the cascade cache are cleared and every element is matched again (`Reload::between` is not asked: `load` returns `None` for a flip). That is the reload that a text change that also moves the window takes. A flip that changes no rule (a rule under two queries needs both) still reloads. The window then draws what the restyle left through `invalidate_after_mutation`, as for any change made natively.

The counters tell the two apart: `elementsRematched` is 0 across a resize that flips nothing and every element for one that does (`js/__tests__/css-media-sheet.test.ts`).

**`@supports`** is decided once, when the rule is parsed, because what it asks does not depend on the window: `(property: value)` by `Validator::supports`, the check a declaration goes through (cached by the same verdict table, without the warning a rejected declaration logs), `selector(...)` by `selector_parse` with a throwaway `Atoms` (so it interns nothing in the document's), and `not`, `and`, `or` and parentheses over them. A block whose condition holds is parsed as if the `@supports` were not there and keeps no condition; one that does not is skipped and is not a skip-log entry; a condition that does not parse drops the block and is recorded as `@supports <prelude>`.

## Definitions: `@keyframes` and `@property`

`definitions.rs`, `keyframes.rs`, `property_rules.rs`, `css/registered_properties.rs`, `motion/keyframes.rs`.

Neither at-rule styles an element, so neither is a `Rule` or in the index. A definition stands in a layer and under `@media` conditions like a rule (`Defined<T>`: the body in an `Arc`, the layer, the `Conditions`), and rides the parse cache with the top-level rule it is in (`ParsedRule::keyframes` and `properties`, mapped to the document's layers when a load assembles). Their `@media` queries are watched like a rule's (`Watched::of` takes the conditions of rules and definitions alike), so a flip reloads the sheets.

**Which definition of a name stands** (`definitions::winners`). The definitions that hold in the window are ranked by layer first and by position second: for a name the last one wins, an unlayered one outranks a layered one, and among layers the one `Layers::order()` ranks highest wins. This is CSS Cascade 5 for `@keyframes` (cascade layers order the rules of one name before their position does) and the last-wins of CSS Animations 1 and of CSS Properties and Values for the rest. A definition whose condition fails is not there and does not hide an earlier one. `StyleSheets::settle_definitions` runs it on every load and keeps the previous result when nothing differs (`SheetKeyframes::replaced_by` compares the rules by content, so a load that touched neither leaves `keyframes.epoch()` and the `Arc<Registered>` as they were).

**`@keyframes`** (`keyframes.rs`). The name is an identifier that is not `none` or a CSS-wide keyword, or a string; `-webkit-keyframes` is the same rule. A block's selector is a comma list of `from`, `to` and percentages from 0% to 100%; a block with another selector is dropped and the rest stay. Declarations are judged by the sheet validator (`Validator::keep`, the check a rule's declarations pass), an `!important` one is dropped as CSS Animations 1 says, and a later declaration of a key replaces an earlier. What can be animated is not decided here: `Keyframes::from_rule` (`motion/keyframes.rs`) takes each declaration through the parser a `defineKeyframes` frame goes through and leaves out the ones that cannot animate or do not parse, logging each, where script throws.

The renderer's keyframes registry takes the sheets' set as a second source (`KeyframesRegistry::set_sheet`); `get` reads it first, so **a name the sheets define wins over `defineKeyframes`**, as the document's rule does on the web, and a script's definition shows again when the sheets stop defining the name. `GpuixView::render` and `build_ctx` hand it `StyleSheets::keyframes` before they build (a number compare when nothing changed), and `dormancy_verdicts` reads the sheets' epoch as well, so a frame asks the elements it found dormant again. A set whose rule did not change keeps its `Arc<Keyframes>`, which is what the animation engine compares: `CssAnimations` already replans a run whose `registry.get(name)` is not the allocation it read, and a redefinition from script changed running animations that way before. The sheets add one case, because script can redefine a name and never remove one: a run whose name has no keyframes any more is cancelled (`reconcile`, `shows_something_new`), as in CSS, and starts again if they come back.

**`@property`** (`property_rules.rs`, `registered_properties.rs`). `syntax` is a string holding a grammar (`*`, or `|`-separated components: `<length>`, `<number>`, `<percentage>`, `<length-percentage>`, `<color>`, `<image>`, `<url>`, `<integer>`, `<angle>`, `<time>`, `<resolution>`, `<transform-function>`, `<transform-list>`, `<custom-ident>`, a keyword, with `+` and `#` on the data types); `Syntax` stores it parsed. `inherits` is `true` or `false`. A rule that does not make a registration is ignored, and logged with its reason with the other skipped rules: a name that is not `--x`, a missing or invalid `syntax` or `inherits`, an `initial-value` that is missing when the syntax is not `*`, that does not match the grammar, or that is not computationally independent (a `var()` or `env()`, a font-relative unit, `currentcolor`, a CSS-wide keyword).

What a registration does (`css/custom_properties.rs`). `StyleSheets::registered` is an `Arc<Registered>` of the winning registrations. It enters the tree where a build starts, `Inherited::with_registered_properties` (the same in `sync_motions` for `motion` elements), which puts the initial value of every registered property into the root's computed map, so `var(--x)` and `getComputedStyle` read it on an element nothing set it on. `CustomProperties` carries the registry down with the map, and `descend` and `inherit` apply it: a property that does not inherit starts from its initial value (or from nothing) at each element and not from the parent's, `inherit` takes the parent's value, `initial` and `unset` the initial one, and a value that cannot be computed (a `var()` with no value, a cycle) is the initial value of a registered property and not nothing. Every place that handed the parent's map down for an element with no custom declaration calls `inherit`, which costs a flag read unless some non-inheriting property has a non-initial value there (`sets_non_inherited`), so a document with a hundred registrations (Tailwind's `--tw-*`) pays nothing at the elements that declare none.

**What a change marks.** The registry and the keyframes are what a build reads that no element's style holds, so a load that changes either (`StyleSheets::take_document_changed`) calls `RetainedTree::sheets_definitions_changed`: a new revision for every subtree and `Dirty::Layout`, as a change of the universal style does. That reaches retention: the custom properties are in the fingerprint of what an element inherits, together with a hash of the registrations (a property that stops inheriting changes no value at the root), and a subtree that read a custom property builds again. Nothing is matched again: no element's rules moved.

## The rule index and matching

`index.rs`. `RuleIndex::build` numbers the rules that apply in cascade source order (sheet by sheet) and puts each selector of each rule in one bucket, chosen by the most selective thing its subject compound requires: an id, else a class, else an attribute name, else a tag, else the universal list. A rule whose selectors are all pseudo-element selectors is left out.

`RuleIndex::matching(element)` visits the buckets of the element's id, its classes, every attribute name some selector reads (and the element has), its tag, and the universal list, runs the full right-to-left match (`matching.rs`, over the `ElementView` trait; `view.rs` is the retained tree's implementation) on each candidate, and sorts the matches by (layer rank, specificity, source number). A rule counts once, at the specificity of the most specific of its selectors that matched.

`share.rs`, style sharing. A flush matches an element in full only the first time it meets that element's key: the type atom (`None` when no sheet names it), whether it is SVG, its id atom, its set of class atoms (sorted, so `a b` and `b a` agree, and a class no sheet names is not there), and for every attribute name any selector of any sheet mentions (`RuleIndex::shared_attributes`, as an HTML or an SVG element reads it) the attribute's value, or only whether the element has an own style for `style`. The key is serialized into one reused byte buffer and looked up by slice, so a hit allocates nothing. What is remembered is the matched list, which the flush interns once per distinct key, so a thousand rows with one look are one match and one intern. It is only valid when every selector the element was tried against is self-contained: `Entry::self_contained`, worked out at index build per selector (not per rule: a rule `.a, .b .c` has one of each), means a single compound with no combinator, no `:root`, no `[style]`, and the same of every argument of `:is()`, `:where()` and `:not()` (a `&` list nested rules share is asked once). The candidates are the buckets the key selects, so the key decides whether it is shareable and the memo records that: a key with a candidate that reads more is marked unshareable and each of its elements is matched in full, as before (a `.list .row` rule makes every `.row` unshareable; a `.cell` is still shared). The key holds every attribute name any selector mentions, not only the self-contained ones, because the presence of an attribute decides which `by_attribute` buckets are candidates. If no selector is self-contained the memo is not consulted. The memo (`StyleSharing`) is a local of `flush_styles`: it lives for one flush, the tree does not change while it matches, and a sheet reload comes before it. The memo is judged in windows, since the elements that open a flush are often chrome that shares nothing with the list after it: a window is 64 lookups of shareable keys (or 64 of unshareable ones, so a flush of those ends its windows too), counting a hit only on a shareable key, and an unshareable key's slot is neither a lookup of the first kind nor a hit. A window with fewer than one hit in four (16 of 64) pauses the memo for the next 256 elements, which are matched directly with no key and no map entry, and then a new window starts with the keys already learned. A flush of unique values builds and inserts about 64 keys per 320 elements, and a list that follows chrome is shared again once the first pause ends. A flush with fewer elements than a window never judges; the next flush starts a fresh memo.

`TreeView::attr` reads an attribute from the element's attribute store (`attributes.rs`, set by wire op 13) and from nowhere else: the store holds exactly the element's DOM attributes, named as the DOM names them. An HTML element stores a name lower-cased and a selector's name is compared lower-cased (`[tabIndex]` reads `tabindex`); an SVG element (`svg`, a tag only an `<svg>` holds, and `text`, see `svg_tree::is_svg_tag`) stores a name as written and a selector's name is compared as written (`svg[viewBox]` matches, `svg[viewbox]` does not). A prop that is not an attribute reaches native as a custom prop only and no selector sees it. `style` is special: the text is synthesized from the element's own style declarations (`kebab-key: value;`, as the DOM's `cssText` has them: a `null` or empty value is no declaration, and a number on a property that is not unitless and not zero has `px`, so `[style*="width: 10px"]` matches `{ width: 10 }`; cached per own-style `Arc`, `StyleSheets::style_text`, and handed to the matcher as a shared `AttrValue`), so `[style*="--dnd-scale"]` works. The attribute operators compare in place (ASCII case-insensitively for the `i` flag), so a check allocates nothing. The cached texts are released at the end of every flush for own styles no element holds, and cleared at wind-down. A `#text` node is not matchable. Storage: an element's attribute store and `ElementCss` (id and class atoms, matched rules) sit in one boxed `Markup` that `RetainedElement` holds directly, so an element with a class and no listener is one allocation and not two (the listener and custom-prop `extras` are a separate box it only has when it needs them). The store is a `SmallVec` of two inline `(name, value)` pairs; a name is an `Arc<str>` shared through the tree's `AttributeNames` table (`class` on five thousand elements is one allocation; the table drops names no element holds once it has doubled past 64), and the class atoms are a `SmallVec` of four. What the store answers is unchanged.

### Matched sets are interned

`cascade.rs`. The result of matching is a `MatchedRules`: the rule numbers in the order their normal declarations apply and the rules with important declarations in the order those apply (layers compare the other way round there: the first layer wins, unlayered rules lose). Equal match lists are interned by a table of weak references (`MatchedInterner`, pruned when it doubles), so a thousand `.item` elements hold one `Arc` and are compared and cached by its pointer.

## The cascade

`cascade::merge` works on declarations as the style prop's JSON would hold them:

1. the normal declarations of each matched rule, in `matched.normal` order;
2. the element's own declarations, in written order (`StyleTable::raw_of` gives the own style's JSON, read back with the lenient parser's `Declarations`), less the ones that are no inline value: `null`, `""` (React DOM's "no value") and a value the validator rejects, so `{color: "bogus"}` does not take back a sheet's `color`. A nested object (a state style) and a custom property pass;
3. the important declarations of each rule in `matched.important` order;
4. the element's own declarations that were written `!important` (`inline_important.rs` strips the suffix of a string value before `StyleTable::intern` parses a payload, so with no sheet it is the plain value; the table keeps the payload as it came and `cascaded` splits the declarations that had it off, in written order). An inline `!important` beats an author one, as in CSS. React hides a Suspense child with it, through the element's live `style` as React DOM does (`setProperty('display', 'none', 'important')`; unhiding sets `display` to the one its props give, else `''`), so `el.style.display` reads `none` with priority `important`, `getAttribute('style')` has it and a `MutationObserver` records the change.

A later declaration of a key removes the earlier one and is appended, which is where `css/covers.rs` reads "written order" from when the merged text is interned: a shorthand drops the longhands before it, a longhand after it stays. A CSS-wide keyword (`apply`) removes the key and the longhands it covers from what came before, and itself stays in the list. `StyleTable::intern` resolves the keywords of the text it parses (`sheet/wide_keyword.rs`, for the merged text and for an inline style with no sheet alike): the keyword is removed, a longhand that an earlier shorthand of the list still covers gets its initial value (`sheet/initial.rs`, which `css/covers.rs` ranks above the shorthand; a longhand with no entry there only has the removal), and `initial` and `unset` (and `inherit` on a property in the `INHERITED` list) are written into the style's `reset`, the names it takes back from the layers under it. `overlay` (`events/state_styles.rs`) clears those names from the layer below before it merges, and puts a longhand a shorthand of that layer still covers at its initial value (`padding-left: unset` over a button's `padding: 1px 6px`). A property whose initial value is a keyword the style parser has no form for (`max-width: none`, `z-index: auto`, `gap: normal`, `sheet/initial.rs` `UNREPRESENTABLE`) is `initial` here too, inline or in a sheet. `initial` and `unset` on `display` write `inline` into the style (no value is a block, so a reset alone would leave the layer under showing), and a reset of a property a `var()` declaration of the layer below holds drops that declaration (`var_substitution::without_reset`); a longhand reset that a held shorthand of the layer below still covers (`border-top-color: initial` over `border-color: var(--c)`) is written at its initial value and the held declaration is laid under it (`var_substitution::keeping`, which is what `merge` does for a value of a layer above). `INHERITED` is keyed by the name the style object writes (`WebkitFontSmoothing`). A style that names no keyword pays one byte search of its text when it is interned (as for `var(`) and carries no `reset`; the search matches a keyword word anywhere in the text, and a property of `UNREPRESENTABLE` only when it is written with its own keyword (`"gap":"normal"`, so `gap: 8` costs nothing), and a text it matches is parsed once more to see whether a top-level declaration is one; the keyword is read at the top level and in the state blocks (`hover`, ..., `state_slot` keys) only, so an `@container` block still drops one. A state block is resolved on its own declarations (`rewrite`), and its `reset` and `revert` lists are set on the parsed block (`Resolved::apply_to`), where `overlay` reads them when the state is folded over the base: `.a:hover { color: initial }` clears the base colour and the block has none. `revert` in a block is also the list `StyleDesc::revert` (and goes into the `reset`): `universal_style::layer_under` writes the lower layer's value for each such property into the block (`state_styles::reverted`), so the state takes the user agent value (a side longhand its part of a shorthand of the lower layer, `SHORTHAND_PARTS`), and a tag with none has the property reset; a declaration of the property or of a shorthand covering it written after the `revert` in the block removes it from the list (`Lists::forget_revert`), so its own value is kept. The focus blocks are applied by the builders as GPUI refinements, which write only the fields a block sets, so a focus block that resets a property is folded into the style before the build instead (`FocusStyles::folded_for_resets`, called in `build_element`, as an element with a transition has them folded), for every builder alike. The universal style's block and the element's own merge with the union of their resets (`refine`), since the merged block is folded over a base none of them saw. The blocks are conditional declarations like the others in `states::merge`, so a keyword is shadowed, kept over and logged for a fold-order disagreement as any value is. `revert` and `revert-layer` stay as they were, a removal of the earlier author declarations, which leaves the layers under. The merged text goes through `StyleTable::intern` and the universal layer (`<UniversalStyle>`) and the user agent style of the tag ([layout.md](layout.md#html-tags)) are put under the result exactly as for an element with no sheet match (`refresh_effective_style`), so the order from the bottom is: user agent style, `*`, rule, inline, `!important` rule, `!important` inline value. A merge whose text does not parse leaves the element its own style and is logged.

### The cascade cache

`CascadeCache`, `StyleTable::cascaded`: keyed by (matched `Arc` pointer, own style `Arc` pointer) and holding a `Weak` to each, which keeps the allocation reserved, so addresses cannot be reused while an entry lives, and no entry pins the own style or the rules. N elements that match the same rules and share an own style cost one merge (`cascadesComputed` counts the misses). The cache is cleared when the sheets change. `release_unused` (run by `StyleTable::sweep`) drops an entry once its key is dead, and only then: the rules are held by no element (the interner and the entry hold them weakly), or the entry has an own style that no element holds (the style table, and the entries whose merge is that style, do not count: a merge that adds nothing to the own style is the own style itself, and without that exclusion many own styles that merge to one style, an inline `left` under a rule's `left: 0 !important` animated per frame, would stay pinned by the entry whose merged style is in use). What an entry's merged style is held by says nothing about whether it can be looked up: an element with a user agent tag style or a universal layer holds the layered style, and the merge is held once by the layer cache, so a rule based on the merge's holders dropped the entries of such elements on every sweep and merged them again. Each pass decides from the counts as they stand when it starts and drops what it found dead afterwards (dropping as it went made the survivors depend on the hash order, which is the entries' addresses), and it repeats while an entry dropped lets go of another's own style. No sheet matches an element: its effective style is the own style, the same `Arc`, and the cache is not asked.

## What a change marks

`invalidation.rs`. When the index is built, `Invalidation::read` walks every selector and records, per feature, where a change of that feature can alter a match, as a `Reach`: nine bits, `{the element, its next sibling, all following siblings} x {itself, its children, everything below}`.

A feature (a class atom, an id atom, an attribute name, and `style`) sits in some compound of a selector. The elements the selector styles are reached from the compound by the combinators to its right: a descendant or child combinator reaches the subtree (children, or everything below), `+` the next sibling, `~` the following siblings, and a sibling combinator followed by a descendant one the subtrees of those siblings. A feature in the subject compound reaches just the element. A `&` list that nested rules share is read once per what the chain of combinators leading to it does to each of the nine places (`Reach::image`), not once per chain, so `& > &, & + &` nested to the depth limit is read in a bounded number of steps. Features inside `:is`, `:where` and `:not` take the position of the compound that holds them, and an argument with combinators of its own is read through them and then through the rest of the selector. `structure` is the reach of an element appearing or disappearing among its siblings (non-empty only when a sibling combinator exists). A feature no selector names has no entry: a change to it marks nothing.

**Structural pseudo-classes** are read by what an element coming, going or moving among its siblings does to them, and the index keeps four reaches (`Positional`, each empty until a selector uses that kind, so a document without them marks nothing for a child that comes or goes). The reach is that of the compound that holds the pseudo-class through the combinators to its right, so `li:first-child .label` reaches the `li` and everything below it, and `li:first-child + li` the next sibling of the element whose answer changed.

| Kind | Read by | A child C comes or goes: what is marked |
|---|---|---|
| `edge` | `:first-child`, `:last-child`, `:only-child` | the element siblings before and after C, one mark each |
| `forward` | `:nth-child()`, `:nth-of-type()`, `:first-of-type`, `:only-of-type` | every element sibling after C |
| `backward` | `:nth-last-child()`, `:nth-last-of-type()`, `:last-of-type`, `:only-of-type` | every element sibling before C |
| `empty` | `:empty` | the parent, for a child of any kind (a text node too), and when a text node's text becomes empty or stops being |

`forward` and `backward` do not mark each sibling as the child comes: a list built a row at a time would mark the rows before each new one, which is quadratic. They note a `SiblingRange` (an anchor, whether it is included, which side), and the flush turns every range under one parent into marks with one walk of its children (`range_marks`, in `positions.rs`, which also holds the hooks). The siblings are those of the anchor as the list stands at the flush, which covers every element that stayed on its side of the anchor, and one that moved marked itself when it was put back. Ranges are noted once each (a set, not only against the last one), so a list built in one batch notes a range per parent, not per row. A removal notes the neighbour that stays, included, since the element it follows or precedes is what counts (a range remembers its parent, and one whose anchor has left it by the flush covers the whole list); an insert notes the new element, not included, since the hook marks it. A move is an unlink and a link, so both places are covered. The hooks are `sheets_unlinking`, `sheets_linked` and, for the text of a `#text` node that goes between empty and not, `sheets_text_changed`; `RetainedTree` calls nothing else. Appending a row to a list of a thousand re-matches the row and the one before it for `:first-child` or `:last-child`, only the row for `:nth-child(odd)` or `:first-of-type`.

A rule `li:last-child` is filed under `li`; a subject that holds only structural pseudo-classes (`:first-child`) is in the universal list and, as any subject with no id, class, attribute or tag, takes the full reload path ([Reloading](#reloading-after-a-sheet-change)). A selector with one is never self-contained, so style sharing does not reuse a match between siblings that stand at different positions.

**`:has()`** is read from the other side. A feature in an argument (a class, an id, an attribute, a tree state, a position) changes on an element below, after or around the anchor, so what has to be marked is not where the selector's combinators lead but where they lead back: from the element that changed, the argument's combinators and its leading one are walked in reverse, and what comes out is the ancestors (`Levels`: the exact number of levels up when every combinator is a child one, so `:has(> svg)` is the parent and `:has(> a > b)` the grandparent for a change of `b`, and "from this level up" once a descendant combinator appears), and the closest or any earlier sibling of the element or of one of its ancestors (`:has(+ p)`, `:has(~ .x)`, `:has(+ .y .z)`). `HasInvalidation` (in `Invalidation::has`, empty and unused unless a selector has a `:has()`, so a document without one marks nothing for it) keeps that per feature, with the `Reach` of the rest of the selector from the anchor (`HasRead`: `.card:has(.err) .title` marks the card with its descendants, `.a:has(.k) + .b` the next sibling of the card, a subject `:has()` just the anchor), and for the anchors, what their compound requires of an element (a `Features`, the one a reload finds elements by: an id, a class, an attribute or a tag, or any element when the compound names none; `:not(:has(.x))` takes the compound that holds the `:not()`). The tree marks only the ancestors and siblings that hold one of those (`mark_has_anchors`), so a class toggled in a list of a thousand rows with no `.card` above them marks nothing. The element that changed is not marked for it: the normal reach of its own features is unchanged, and an anchor's own features go through it as before.

A child that comes, goes or moves (once, at the hooks) is read two ways. For an argument whose combinators go down only (descendant and child, after a leading `>`, `+`, `~` or none) and that reads no position, it changes the anchor only by being, or holding, a match of the argument's subject (the rightmost compound), so the anchors above it are marked only when the child or something below it holds what that compound requires (an id, a class, an attribute or a tag: a `Features`, as for an anchor). The subtree is walked once for all the arguments (`structure_read`, before it is unlinked for a removal), which is what matching it costs when it comes anyway. None of this runs for a child whose parent is not connected to the root (the `is_connected` the flush uses): a subtree built bottom-up apart is matched, with everything below it marked, when it is put in, and that insert walks it once; a removal from a connected parent still walks the removed root once. So `html:has(.dark) .card` over a list of ten thousand rows re-matches only the new row when a plain one is appended or removed, and the whole document when a `.dark` element comes or goes. A leading `+` also marks the element sibling right before the child, whatever it holds, since what comes right after the anchor is what the anchor has next. Every other argument (a sibling combinator inside it, a position read, a subject that requires none of those, a combinator inside `:is()` or `:not()`) is read as any element: it may match, or sit in the way of a sibling combinator, so the anchors are the ancestors up to the deepest the argument can hold (`:has(> svg)`: the parent only; `:has(svg)`: all of them) and the earlier siblings of those levels. The ancestors are marked at once, the earlier siblings as a `SiblingRange` that the flush expands once (the same one the structural pseudo-classes use, with the anchors among them marked, filtered by what an anchor requires), so a list built a row at a time under `.row:has(~ .done)` scans no siblings per row. A range remembers the parent: if its anchor has left it by the flush (moved, or gone), the whole list is covered, which is what makes an edit that is undone by a move in the same batch right. That holds for a counting range, whose elements mark themselves when they move; a range of anchors is filtered by what an element holds, so an element that moves without the subject's features marks nothing. So a range of anchors keyed on an element that is unlinked (a sibling, or an ancestor of the change at a level above the first) is widened to the whole list of its parent at the unlink (`PendingRanges::anchor_leaving`, a set of the keyed ids checked at `sheets_unlinking`). An anchor compound with `:root` is the root element alone.

A position read in an argument (`:has(:first-child)`, `:has(> :empty)`) is changed by the siblings of the child and by its parent, which are below the anchors above them, so a child coming or going marks the ancestors that hold what their compound requires; only an argument that also has a sibling combinator (`:has(+ :nth-child(2))`) has anchors among the siblings of the child and of its ancestors, and notes their ranges. A text node going in, out, or between empty and not changes only `:empty`, so it reaches an anchor only when some argument reads it. A combinator inside a `:is()`, `:where()` or `:not()` in an argument (`:has(:is(.a .b))`) relates the feature to the anchor by no fixed place, so a change of such a feature, and any child coming or going, matches every element again. A reload of a rule whose subject has a key and a `:has()` is scoped by the key; one whose subject is a `:has()` alone has no feature to find elements by and reloads everything.

The tree's hooks (`tree.rs`) collect `(element, Reach)` marks:

| Change | Mark |
|---|---|
| class attribute (symmetric difference of the atom sets, plus the reach of `[class]`), `id`, any other attribute | the reach of what changed |
| own style change | the reach of `[style]`, which is empty unless a selector reads it |
| a class, id, attribute, own style or tree state that a `:has()` argument reads | the anchors above or before the element that hold what their compound requires, with the reach of the rest of the selector |
| element inserted or moved | the element and its subtree, plus `structure`; the `:has()` anchors it can change |
| element about to be removed | the next matchable sibling, with `structure`, since what follows matches without it; the `:has()` anchors it can change |
| `disabled`, `formControl`, `required`, `readOnly`, `href`, `type`, `popover` or `popoverOpen` of an element, or its checkedness or `indeterminate`, when a selector reads a tree state that it changes | the reach of those states |
| text of a `<style>` element, `<style>` inserted, removed or moved, root changed, constructed sheet changed or the adopted list changed | the sources are dirty: the elements the changed rules reach match again, or every element ([Reloading](#reloading-after-a-sheet-change)) |

### The flush

`flush_styles`, called once at the end of `apply_batch_to_tree`, after the last op, so a batch matches each element once however many ops touched it:

1. If the sources are dirty, `reload_sheets`: collect the texts of the connected `<style>` elements in tree order (`tree_path` compares positions among siblings), then the adopted constructed sheets in list order. If they equal the texts the index was built from nothing happens; otherwise `StyleSheets::load` parses all of them again with one `Atoms` and one `Layers`, validates, builds the index, and then either brings the elements to it by the rules that changed ([Reloading](#reloading-after-a-sheet-change)) or clears the interner and the cascade cache and marks everything.
2. If the atoms are not fresh, compute them for every element and mark everything.
3. Expand the marks into the set of elements to match (`restyle_set`, `Expansion`): each reach becomes the element, its children or its subtree, and the next or following siblings, each element once and each subtree walked once. The marks that reach siblings are grouped by parent (`expand_siblings`): one map of the parent's children gives their positions, and the following siblings are walked once from the first mark with the reaches of the marks before each folded together, so mounting n siblings under a sibling combinator is linear. A mark of everything is the document in tree order plus the elements outside it (which match nothing).
4. Match each (`elementsRematched` counts them; `SiblingPositions` in `view.rs` gives `prev_sibling` the element's index among its siblings in O(1), mapping a parent's children the second time it is asked, so `+` and `~` do not scan the siblings per step; the same pass remembers, per parent and per `~` in a selector, the first earlier sibling that satisfies the rest of the selector, so `.x ~ .item` over n siblings is n steps whether or not a `.x` exists), intern the result, and compare it to the element's current `matched` by pointer.
5. `apply_matched` for the ones that changed: store `matched`, `refresh_effective_style`, `settle_style_change`. That is the path `set_style` takes, so retention, the transition source style and the paragraph grouping see an ordinary style change. An element no frame has built has no transition source style: what a batch assigns it before the cascade lands (its own style, the user agent style, then the sheets' result) is not a style anything was drawn with, and CSS never transitions the first style of an element. Such an element is in `RetainedTree::fresh`: from `create_element`, and again from `detach_child` for the element and everything below it (a browser gives an element outside the document no computed style, so what it has when it is inserted is a first style, whether it was created detached or removed and put back in a later batch). `GpuixView::render` calls `note_frame_built` once the root is built, which removes from the set every element connected to the root; one that is not connected stays in it however many batches pass, and `destroy_element` removes it. Freshness ends when an element is first built, not when the batch ends: Solid flushes a batch per microtask, so an element created in one and given a class in the next, before any frame, has still not been drawn. `set_style` compares the interned style by pointer, not the parsed style, which has dropped `!important`: `{ color: "red" }` to `{ color: "red !important" }` restyles.
6. Drop the `[style]` texts no element holds (the cascade entries go at the style table's next sweep), and wind down if no sheet is left.

Whether a moved or removed element holds a `<style>` element (`contains_style_element`) is answered by walking its subtree when that is small next to the number of `<style>` elements, and from the `<style>` elements up to the root when it is not.


### Reloading after a sheet change

Rules are numbered in cascade order across every sheet, and a matched list is made of those numbers, so inserting a rule renumbers every rule after it. Three things keep a change from costing a match of every element.

**The parse cache.** `parse_cache.rs` cuts each source into top-level rules (`split_rules`) and keeps what each rule text parsed to, as `Arc`s the index shares: a rule parses once against a layer tree of its own (`LocalLayer`, a type that does not index the document's tree), replayed into the document's in source order, and a load of unchanged rules clones nothing. The cache keeps the texts of the last load and, per source, the rules it was cut into: a source whose text is the last load's is not cut or looked up again, so changing one `<style>` does not pay for a large one that stayed. The cutter has to agree with the tokenizer on where a rule ends. `url(` opens a url token only when the ident that ends at the parenthesis is exactly `url` (`myurl(`, `-url(`, `#url(` and `@url(` are plain parentheses); an escape the cutter cannot place (a `\75 rl(` or `ur\6c(` that spells `url(`, an escape beside the ident, a closer that matches nothing, an unterminated string, comment or block, a newline in a string, a rule with no block) makes it return `None`, and that source is parsed whole, with the same result and no scoped reload. An escaped name that is not beside a `(` is no such case: Tailwind's `.md\:flex`, `.w-1\/2` and `.w-\[calc\(100\%-1rem\)\]` are cut.

**The plan** (`reload.rs`). `StyleSheets::load` compares the top-level rules of the load before with this one by allocation: the rules they share at the start and at the end keep their selectors and declarations, and what lies between is the removed and the added rules, one region (`Reload`). `RetainedTree::plan_reload` then decides, reading and changing nothing, what the change reaches:

- The elements that matched a removed rule. The interner is scanned once for the live lists a renumbering changes (`MatchedInterner::renumbering`: a list is gone when it read a removed rule, else it is replaced by the renumbered one), which gives the lists by address, and one walk of the elements finds the ones that hold a gone list (reached) and the ones that hold a replaced list (`holders`). A list that read only rules that kept their number is not in it.
- The elements an added rule can match, found by looking at the elements and not by matching: each selector of an added rule needs an id, class, attribute or tag of its subject compound (`Features`, keyed as the index keys a selector, the others it needs checked on the element), so an element is reached if it has them all. The tag of an element is read only when a tag feature asks (`Read::tag`), so an element already reached by an id or a class never reads it.

The same walk counts the elements reached. If more than half are, the plan is `None` and the caller matches every element, which costs less than the bookkeeping.

**The apply** (`apply_reload`) changes what the plan found and nothing else: the interner replaces the changed lists (`MatchedInterner::replace` drops the changed lists from the interner with one `retain` over it, which also drops the entries whose list is gone, and interns the renumbered ones; every changed list is still held by an element when it runs, because the holders are swapped after it returns, so no new list can take the address of a replaced one), only the `holders` get their `matched` list swapped for its replacement, the cascade cache entry of each replaced list moves to the new one (the same declarations apply in the same order, so the cascaded style is the same), and the reached elements are marked (`Reach::SELF`) for the flush to match as it matches any marked element. Every other element is not visited. The index itself is built again, which is what recomputes `may_match`, `shares`, the attribute names and the reach tables.

**Atoms.** An element keeps the atom of a class or id only when a sheet names it, so a load that interns a name some element carries has to give that element the atom, whatever else the load changed and even when no rule enters the index for it. The case that shows it: `.card::before { ... }` interns `card` but its selector is dropped (no selector that names a pseudo-element matches an element), so the load adds no rule; a `.card` rule that comes in the next load would find no element holding the `card` atom unless the first load had given it. A load that interns names reads again exactly the elements that carry one (`read_atoms_of_new_names`): those whose `id` equals a new name or whose `class` has one as a whitespace-separated token, found by one read-only pass over every element's `id` and `class` against a set of all the new names, with no cap on their number. An element that holds a name only inside a longer one (`latest` when `.late` arrives, id `late-menu`) is not read. A name interned for a tag or attribute is checked the same way and reads the elements that happen to carry it as a class. Nothing is kept per name, so an insert of a new class costs that pass and a read of the elements that carry it. A load that interns nothing skips all of it. The atoms are read for every element (`init_all_css`) only when they are stale, which is when sheets are first enabled.

The load falls back to matching every element (clearing the interner and the cascade cache) when any of these holds, and a test names each: a source was parsed whole in either load; a rule that stays changed its layer rank or the unlayered rank moved (an `@layer` added or removed); an added rule's subject needs none of an id, class, attribute or tag (`*`, `:root`, `:not(.a)`; an `:is()` or `:where()` subject, which is what `&:hover` nested in `.a` is, takes the features of its arguments and falls back only if one has none); mark-all was already pending or the atoms were not fresh; or more than half of the elements are reached.

Measured (`profile-stylesheet-cost`, `runtime` mode, 10,000 items, batch Minstr): `insertRule` of a rule nothing matches 1.1; with a class name no rule had before 6.8 (the pass over every element's `id` and `class` that finds the elements to read, about 0.55 Minstr per 1,000 elements); a rule matching one element 0.8; a second `<style>` with an unrelated rule 2.5; a rule matching every item 93, which is a match of every item whatever the reload does. With 3,000 unrelated rules in the sheet the first is 7.5, the cost of indexing them again.

An element that is not in the document, or is not matchable, matches nothing: removing a `<style>` element restores every element it styled.

## Sheet sources

- **`<style>` elements.** An element of type `style` registers in `style_elements` when created. Its sheet text is the concatenation of its `#text` children. It takes part while connected to the root, in tree order. `display` reads `none` for it (`RetainedElement::display`), so layout skips it and the build never draws it. Solid lists `style` as an element type (`isElementType`) and React's host config forwards any type and a string child becomes a `#text` node as anywhere.
- **Constructed sheets**, wire ops 14 and 15 (`batch/wire.rs`, `BatchOp::SetStyleSheet`, `SetAdoptedStyleSheets`). `constructed` maps a sheet id to its text; `adopted` is the ordered list that applies, after the `<style>` elements. A sheet in the map and not in the list does nothing. Sheet ids are a namespace of their own.

## Attributes and wire ops 13 to 15

Op 13 `setAttribute(id, name, value | null)` stores into the element's attribute store; the JS adapters forward every prop that `element.attributes` lists (`attributesOfProps` in `js/dom/attribute-names.ts`: not `children`, `key`, `ref` or `style`, and no handler or object), named by `attributeNameOf(prop, svg)` and valued by `attributeText`, the two functions `getAttribute`, `getAttributeNames` and `MutationRecord.attributeName` use, so the native store and the DOM agree by construction (an `<input>`'s `checked` and `value` attributes have two props that can answer, `checked` and `defaultChecked`, `value` and `defaultValue`, and `inputAttributeValue` is the one rule that picks: `attributesOfProps`, `attributesWritten` (what each adapter sends when one prop is written) and `getAttribute` all call it) (see [reference](../reference.md#listeners-and-dom-members-on-an-element)). `setAttribute`, `removeAttribute`, `toggleAttribute` and `dataset` on an element write the prop through the adapter's own prop path (`DomElementBinding.writeProp`: React's `writeInstanceProp` runs the same `diffCustomProps` and `diffAttributes` a commit does, Solid's calls `setHostProperty`), so they reach the store by the route a rendered prop takes, the gate included, and a `MutationObserver` gets one record per write. `getAttributeNames` and the observer's records count `style` as an attribute (`isNotAttribute`), but a `style` is never sent as one (`isNotNativeAttribute`): native builds its `[style]` text from the element's own style, which `element.style` writes through `setStyle`. A write the DOM keeps only as text (`on*`, `key`, `ref`, `children`) is kept in JS for `getAttribute` and is not sent, so no selector sees it. A prop native also reads (`id`, `tabIndex`, `width` on a canvas) goes as an attribute and as a custom prop; `class` and `data-*` go as op 13 alone, never also as a custom prop, so an element of any type pays one op for each. Nothing in native reads an attribute but the cascade, so an app with no sheet sends none (see below).

### The attribute gate

`js/css/attribute-gate.ts`. Every attribute send of an adapter goes through its mutation queue's `setAttribute`, which drops it while the gate of the queue's renderer is closed; the JS side (`getAttribute`, `dataset`, props) reads JS state and does not notice. A gate opens, for good, the first time a sheet can apply to that renderer: a `<style>` element is created (`createElement` of type `style`), a constructed sheet's text is sent (`setStyleSheet`) or the adopted list becomes non-empty (`setAdoptedStyleSheets`; a renderer created while sheets are adopted opens when its queue registers). Opening it makes every queue of the renderer send, first, the attributes of the elements it already holds (`MutationQueue.backfillAttributes`), read from the adapter's own registry of mounted elements through `ElementSource` (`setElementSource`: Solid's `HostRoot.elements`, React's `Container.instances`) with the same `attributesOfProps` the live sends use. React skips its own sends while the gate is closed (`MutationRenderer.forwardsAttributes`), since the backfill reads its instances' current props; Solid skips them too, and the backfill fills its per-node record of what it sent (`ElementSource.rememberAttributes`, which the queue calls with the attributes it just sent), so a later removal or an unchanged write is judged against what native holds. The backfill is queued ahead of the sheet op, except for a `<style>` element, where it follows the element's own `createElement` (Solid lists a node as mounted before its element is queued). Native applies a batch's ops in order and restyles once at the end, so no element is matched before it has its attributes. Once open the gate stays open: closing it would need native to forget the attributes. The test renderer's `getAttribute` reads native, so a test that reads it mounts a `<style>` first. Ops 14 and 15 carry the constructed sheets. All three are in the binary batch (`js/wire.ts`, `WIRE_OPCODE`) and decoded by `wire-testing.ts` for the tests. Layout of each is in [reference](../reference.md#wire-format).

## The JS side

`packages/native/js/css/`, framework neutral:

- `rules.ts` splits sheet text into top-level rules (strings, comments, escapes, parentheses and nested braces; an at-rule ends at its block or a `;`, a style rule only at its block, as in the native parser). A `}` with nothing open starts the next rule's prelude, as in CSS Syntax and the native parser, so that one rule is dropped with its block and the rules after it stay; a constructed sheet and a `<style>` with the same text list and style the same rules. It does not interpret a rule. `CSSStyleSheet.cssRules` lists what it finds.
- `style-sheet.ts`: `CSSStyleSheet`, `CSSRule`, `CSSStyleRule`, `CSSRuleList`, and `CSSMediaRule` and `CSSSupportsRule` (the `conditionText` and `media.mediaText` of the prelude, and the rules between the braces as `cssRules`, cut by the same splitter; read-only). Every change to the rule list calls `sheetChanged`, which sends the whole text (`sheetText()`: the rule texts joined by newlines).
- `observable-array.ts`: a `Proxy` over an array that checks every value (`convert`) and reports once per change; the mutating methods are wrapped so they are one change, not one per element they touch.
- `adopted.ts`: `document.adoptedStyleSheets`, one array for the document.
- `sheet-sync.ts`: what reaches native. Sheets are per native tree, so there is one record per renderer (not per queue): the ids of the sheets whose text it holds and the adopted list it holds. `registerSheetSink(renderer, queue)` is called by `createMutationQueue`, which is how a renderer mounted after sheets were adopted gets them. A change computes what each renderer lacks: `setStyleSheet(id, text)` for a sheet it has not seen or whose text changed, `setAdoptedStyleSheets(ids)` when the list differs from the one sent (a sheet listed twice counts at its last place, a disabled sheet is left out), and `setStyleSheet(id, null)` for a sheet that left the list. The ops go through any live queue of the renderer, so they ride in its next batch like every other op. A change to the text of a sheet native already holds does not write at once: the sheet is marked dirty (`RendererSheets.dirty`) and its queue told (`sheetsDirty`), and the queue writes one `setStyleSheet` per dirty sheet as it starts to flush (`flushDirtySheets`), so n `insertRule` calls in a tick are one op of n rules, not n ops of growing text. Adoption, enabling and removal still write at once, and the gate is open by the time a held sheet changes, so the backfill still precedes every sheet op.

- `mutations.ts`, `deferWrite(key, write)`: the write of a whole element style by code (`element.style`, `setAttribute('style', …)`) is not queued at once. It replaces the pending write of that element, so a burst (a drag writing `transform` on every pointer move) is one `setStyle` of the last style. `flushMutations` runs the deferred writes first, then flushes the dirty sheets, then sends the batch, so a deferred write lands after the ops that were queued before the flush (the `setStyle` of a commit made earlier, the `createElement` of its element). A deferred write may queue ops but must not defer another write: that one would run in the next flush, not the one that is under way. The write itself checks, when it runs, that the element is still mounted (one removed since is gone from native) and that native has not been sent that style already (a framework commit between the call and the flush may have sent it): Solid's `writeStyle` and React's `sendLiveStyle` both ask `SentWrites`.
