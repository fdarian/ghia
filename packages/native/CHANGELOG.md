# @ghia/native

## 0.12.1

### Patch Changes

- 9100adc: `createMutationQueue` walks a style for `blob:` URLs only when the style's JSON text contains `blob:`, instead of walking every style it sends.
- 9100adc: The mutation batch is one binary byte array instead of JSON text. `createMutationQueue` writes each op as it is enqueued through `WireWriter` (internal to `@ghia/native`, `js/wire.ts`; not exported) into reused buffers, with no tuple per op and no `JSON.stringify` of the batch, and `applyBatch(bytes: Uint8Array)` on the live, test and wasm renderers decodes it in place (`batch::wire`), so the napi call transcodes no string and the decoder allocates nothing per op beyond what it keeps. The format is specified in `docs/reference.md` ("Wire format"). **Breaking for anything that calls `applyBatch` itself**: it takes the bytes, not a JSON string; tests that built or parsed a batch use `encodeWireBatchForTest` and `decodeWireBatchForTest` from `@ghia/native/testing`. `MutationRenderer.setStyle` takes the style's JSON text as an optional third argument, which Solid passes from the text its write comparison already made, so a written style is stringified once. A failed batch is put back in front of what was enqueued since, and a style native rejects is cut out of the batch by its byte range, as before.
- a1ba92a: The children plan of a host element (its paragraphs and blocks, and the text a `<text>` reads out) is kept on the element and found again while its subtree, the `white-space` it inherits and the `display` and `order` its `@container` blocks gave are unchanged, instead of planned in every build: 50 rows built whole cost about 55k fewer instructions a row (a column 45.07M to 42.31M a frame, a list 60.79M to 58.05M). The switch is the style cache's (`setStyleCache`, `GPUIX_STYLE_CACHE_OFF`, and `GPUIX_RETAIN_VERIFY` plans again for every kept plan and asserts the two equal); `getBuildCounters()` has `plansKept` and `plansComputed`.
- 57bab8d: A commit that only changes how elements paint is drawn as a patch frame, as a hover that only paints is: the roots that hold the restyled elements are built again and gpui writes the primitives they paint over the frame shown, and the layout stays current, so a read of `scrollTop` or `clientHeight` after the commit runs no layout pass. A restyle qualifies when it keeps the operations of the root (the comparison a hover makes: colours that keep their visibility, an opacity on the same side of 1, a background quad that is kept in both styles), and a state style (`hover`, `hasHover`, `focusVisible`, ...) whose refinement differs only in paint is a paint change now (it made the style a layout change, so the mailbox row of ghia-bench took a layout pass for a selection). Anything else, or an element no root of the last frame built whole holds (`getPatchCounters().unpatchable.Commit`), is drawn whole as before.
- 5bf8afb: A commit whose layout and structure changes all lie inside a scroller (an overflow `auto` or `scroll` element that holds nothing else the retention excludes) is drawn as a patch of that scroller, whatever it holds (text, boxes with children, a keyed swap of the content with another number of elements; gpui splices the ranges of the scroller into the frame): the scroller is built and laid out again and gpui accepts the patch when nothing outside it moved (`getPatchCounters().relayoutPatches`, `rewrittenRecordings`), where it was a frame built whole. A change outside every scroller is counted as `unpatchable.Structure`, a patch whose box would leak out as `declines.NotContained`. A read of boxes or scroll metrics between the commit and the draw is answered by that patch, prepared ahead of the draw (`Window::prepare_patch`), instead of a layout pass from the window's root, and the draw finishes it without building the scroller again; a mutation or a scroll write after the read discards it, and a patch gpui declines at the read falls back to a pass. Consecutive commits in a scroller are all patches. Needs the contained relayout patch of the zed submodule, which a window opts in to.
- 14d6582: A div keeps gpui's interactive element state only when something reads it (focus, scrolling, a click, drag or hover listener, an active or hover style, a tooltip), so a plain host div with an id skips three element-state map round trips per frame: 50 rows built whole cost 21k fewer instructions a row, a patched list crossing 3.110M to 2.993M. A mouse press over a plain div no longer asks the window to refresh. This is an engine patch in the zed fork, always on.
- 14d6582: The bounds of a host element are read by one shared layout probe instead of two boxed listeners, the bounds registry updates a box where it is stored, and a stacking context moves each lifted entry once. A column of 50 rows built whole costs 2.7% fewer instructions (942.2k to 916.7k a row), and `onLayout`, `getBoundingClientRect` and the observers read the same numbers.
- 4a139f0: A hover that only paints (a row that takes another background colour under the pointer) no longer holds a list's scroll as a frame built whole: a wheel over the rows of ghia-bench's mailbox is a translate for 693 of the 720 ticks of its scroll phase (396), and the tick that follows a crossing repaints the row the pointer left and the row it entered where the translate put them. A hover that more than paints, or that a listener hears, is a frame built whole as before. The scroll phase's median is 4.37M instructions a tick (5.56M), its mean 7.14M (7.6M); row crossings are 4.60M (4.62M). `getPatchCounters().scrollPatch` has `hoverAsked` and `hoverMatters`, which tell a wheel whose pointer is not where the frame shown had it from a hit chain that matters. The engine is zed at 6231b52b34: a wheel on a list goes on from where the list is now, and a patch of a row painted in its region does less work.
- 381e84f: A commit that restyles rows and swaps the content of a scroller, a read of layout after it and a programmatic scroll of a `<virtual-list>` (`scrollTo`, `scrollTop = n`) are one draw: the patch the read prepared is finished, the restyled rows are patched where they stand, and the rows are moved by a translate that builds the row that comes in, where the draw was a frame built whole. A write to a list's offset notifies no view, so it no longer discards the patch a read prepared; a frame whose translate declines is built whole at the new offset, as before. A restyled row of a virtual list that the frame shown does not hold needs no patch (a scroll that brings it in builds it with its new style), so a commit that restyles one is no longer `Commit` at the read. `getPatchCounters().scrollPatch.composed` counts the translates that came after a patch in the same draw. Needs the patch-and-translate draw of the zed submodule.
- a5db856: A `<virtual-list>` tells its list the size of a row whose root style fixes it (a `div` with a `height` in px and a width that is in px or fills a block, padding, margins and borders in px, no min or max size, aspect ratio, container block, motion or transition of a size, and states that only paint), so the rows it does not show are no longer built and laid out in a scratch frame to be measured, and a row that comes into the overdraw of a scroll is built once, where it shows. The list checks every row that shows against what it was told (`getPatchCounters().scrollPatch.declarationMismatches`), and `rowsMeasuredByLayout` and `rowsMeasuredByDeclaration` count how the rows were measured. `GPUIX_LIST_SIZES_OFF=1` turns it off for a measurement. `getPatchCounters().deferredSceneRebuilds` counts the patches that left the scene to the translate after them. Needs the zed submodule at `8434d5c7ad`.
- 6c9f646: The root of a virtual-list row hits the style cache: that a row does not lift is a build input said after its style (`stacking::absorb_lift`), not a flag on a clone of its `StyleDesc`, so the row's style is the element's own `Arc` and no `StyleDesc` is cloned per row. 50 rows built whole: `styleDescClones` 99 to 0, `styleAppliesReplayed` 414 to 463.
  
  A virtual-list row whose root is a custom element (`<img>`, `<input>`, `<textarea>`, `<markdown>`, `<code>`, `<diff>`, `<svg>`, `<webview>`, `<anchored>`) or a nested `<virtual-list>` is built unlifted as a host root is, so its element and its retained record agree again.
- a424e75: A row of a virtual list is recorded for the travel of a row that shows (three heights of the list plus its overdraw past the clip, where it was half a height), so a scroll that brings a row in no longer builds a second row again where it is for the region of its recording: the navigate proxy of ghia-bench's mailbox builds one row a key and none again, its App median is 36.9M and 36.1M instructions a key (38.5M), and the scroll phase's mean is 5.51M a tick (7.15M). Other scrollers keep half a viewport.
- 3b381be: A programmatic write to a `<virtual-list>` offset (`scrollTo`, `scrollTop = n`) and a wheel that changes which rows show are drawn by moving the rows that stay, taking out the rows that leave and building only the rows that come in, when the rows that come in have a measured size, where the frame was built whole: the picture, the boxes, what is under a point and where a click goes are those of the frame built whole. `getPatchCounters().scrollPatch` counts them (`membershipFrames`, `rowsBuilt`, `rowsRemoved`) and says what held the others whole (`held["Membership.unmeasured"]`, `Membership.unmeasuredOverdraw`, `Membership.settles`, `Membership.disjoint`, `Membership.noBuilder`). Needs the list scroll patch of the zed submodule.
- 14d6582: A window on macOS draws only the part of the picture that a frame changed (a hover patch, a list scroll, a scrollbar's fade) and keeps the rest. It is always on, with no option and no environment variable. The picture is the same; a patch frame costs about a third of the GPU time on the mailbox of ghia-bench and a frame built whole 8% more. A scene with an effect group or a surface, a transparent window and a window with native views are drawn whole. `TestRenderer` gets `presentFrame` and `capturePartialPicture`. `GPUI_GPU_TIMES=<file>` logs the kind, GPU time and damage of each presented frame.
- 6719139: A row of a virtual list and a root with no root of its own in it are patch roots, so a commit or a hover on a row that declares no hover is a patch frame.
- a0cfc02: The per-element work of a patch is cheaper: a restyle that only paints is judged once for the pair of interned styles it goes between (the border shorthands and the pointer-state refinements were parsed and folded again on every `setStyle`), the scan for patch roots asks the style of each element once, and a patch compares the tape it captured with the recording by what the writes hold, where it compared strings made by `format!` and `Debug`. The zed gitlink brings the shape store's cache of a text's width-independent marks, and `getLayoutCounters()` reads `snapComputations`, `snapCacheHits` and `endReshapeComputations`. On ghia-bench's mailbox the navigate proxy's App median is 32.0M instructions a key (33.4M with the snap cache alone, 36.5M before), and a hover crossing a row costs 3.66M (4.60M).
- 14d6582: The embedded run loop pump no longer calls `updateWindows` on every tick (AppKit updates the windows once per event itself) and re-arms its two run-loop watches in one `kevent` call: a pointer move costs 2.2% fewer instructions (0.594M to 0.581M).
- 14d6582: Recording a subtree for retention is cheaper: a retained root keeps its recording state boxed (4 KB to about 100 bytes moved at each phase) and builds its id once, and the tape of a root that is built again is the last build's, emptied in place. Recording a column of 50 rows costs 13% fewer instructions (66.55M to 57.75M); a frame that replays or patches is unchanged.
- 9282468: A list scroll measures the rows of the overdraw that have no size before it is classified, and builds a row that stays but no longer fits where it was recorded in the translate, where either held the frame whole: the keys of ghia-bench's mailbox that scroll the list are one patch and one translate (21 of 22 composed; the App median of keys 2 to 30 is 38.3M instructions, from 44.9M), and the scroll proxy's median is 5.56M (6.85M). `getPatchCounters().scrollPatch` has `rowsRebuilt`. A row built again is in the registries once (what it wrote before is taken out as the build starts, and the page forgets its records as it forgets a row that left), and a frame that kept no row in place settles the rows that left, where their boxes stayed. A patch of an anchor or a row, and the rows that left, no longer expand the replays a registry has not read to replace what they wrote (hover row crossings 4.70M, 4.62M).
- 14d6582: A hover after a wheel scroll is a patch frame again, and a step of a list's scrollbar fade is a repaint of the thumb, not a frame built whole. A row that a hover patched during a wheel left an id in the retention bookkeeping that no longer existed and every later hover was declined; on ghia-bench's mailbox the hover after a scroll goes from 0 of 480 ticks patched (crossing median 7.8M) to 18 of 480 (3.5M), and 243.7M to about 120M for the phase. A prepared patch no longer adds a start region for each element of each patched row, so a long run of hovers leaves the registries the size they were.
- e1c7649: `scrollToItem` on a virtual list reports the rows the list shows after the scroll in `onVisibleRange`, as a wheel to that position reports them. A row near the end used to report the row and the next (`[last, last + 1]`) while the list showed the last viewport's worth of rows, and the native addon's `scrollToItem` reported nothing. The range is read from the paint of the frame that applies the scroll, after the layout has held the position to what the list can scroll to, so the event comes with that frame and not inside the call.
- 5a6650c: Dragging a virtual list's scrollbar thumb or clicking its track reports `onVisibleRange` as a wheel does (the DOM fires `scroll` for it), and `scrollTo` or `scrollTop` that rests a bottom-aligned list at its end reports the rows it shows, not `[count, count + 1]`.
- 14d6582: The step that applies a declared style to a host div is kept per interned style and colour and length context, and the next element with the same style has the result laid over its div: 50 rows built whole cost 5.7% fewer instructions (1000.7k to 943.9k a row), a patched list crossing 2.1% fewer. A style that a state, a transition, a motion, an animation, `var()` or the `rtl` mirror produced is applied each time, as before.
- 14d6582: A plain text is one gpui element instead of a wrapper div, an underlay canvas and the glyphs (three drawables, three layout nodes and three dispatch nodes fewer per text), so building a row of ghia-bench's mailbox costs about 190k instructions less (50 rows built whole: 1188.7k to 998.5k a row), a patched hover crossing 10% less and a keystroke of the navigate phase 4% less. Selection, find highlights, the cull outset and the pictures are the same. A paragraph with a ring, an opacity group, a cursor or region hitbox, a focus anchor or an atomic inline keeps the wrapper.
- afade40: `onVisibleRange` of a `<virtual-list>` fires when the scroll position is written, not only for a wheel. `scrollTo`, `scrollTop = n` and `scrollBy` (an app's keyboard navigation) moved the list without reporting the rows that came into view, so an app that moves a window of rows from `onVisibleRange` stopped following after its first window and the list went blank (after about 52 arrow keys in the mailbox example). A write now reports the range a wheel to the same position reports, once, and a write that leaves the list where it is reports nothing. `scrollToItem` reports the rows that show at the row it scrolls to, where it reported the item and the next.

## 0.12.0

### Minor Changes

- 4c7d9c6: In the native build, `window` (the global object itself), `document` (Ghia's document) and no-op `scrollTo`, `scroll` and `scrollBy` are installed as globals by the new `@ghia/native/dom-globals`, which `@ghia/native/host` imports, so every Ghia UI has them; the wasm build runs in a real browser and installs nothing. `addEventListener` and `removeEventListener` on the global object register with both Ghia's window target and the runtime's, so `keydown`, pointer and focus events reach them while `error` and `unhandledrejection` keep working. `isWebBuild` is exported from `@ghia/native/host`: `true` in the wasm build, `false` in the native one. Use it instead of `typeof window`, which is now `"object"` in both. Web libraries such as TanStack Query and Router, whose client code reads `window` and calls `scrollTo`, now run it.

### Patch Changes

- 8fcd806: An app serves the automation protocol on stdin only when `GPUIX_AUTOMATION=1` is set in its environment. It used to turn on whenever `process.stdin` was not a terminal, so an app started by a harness with a pipe or closed stdin (or from Finder) loaded zod and eventsource-parser and read stdin for nothing. `launch()` sets the variable in the child; a driver that spawns the app itself and speaks the protocol must set it too, and there is no fallback to the terminal check.
- 7528529: A `backdropFilter` blurs the content painted after a `<nativeview>` or `<webview>` that is under it. The filtered backdrop went over the layer above the view, which starts out transparent, instead of replacing what the layer held under the box, so the sharp content showed through the translucent blurred copy and the blur read as nothing. It now replaces it, on a transparent window too.
- 8fe6300: The blink of a focused `<input>` is a patched frame that builds the input alone when the page holds a `<virtual-list>`. A virtual list or one of its rows made the frame before it unsteady (`Exclusion::varies_with_time`), so every tick of a loop or caret elsewhere on the page was drawn whole and rebuilt the visible rows (about 2.4 ms a blink in a mail client with a search box). A list is painted as the frame that built it left it, and what changes it afterwards (a scroll, a new window of rows, an animation in a row) is a source of its own, so a tick no longer waits for it.
- 9be6797: Draw orders cost less to work out: gpui's bounds tree checks the last 16 bounds it was given before it searches, and stops at one that encloses the new bounds, as a row's background encloses its text. The orders are the same. The scroll of the mailbox app of ghia-bench takes 7.50M instructions a tick against 7.87M, its patched ticks 2.93M against 3.37M, and a row's hover background no longer costs anything in a scroll.
- c936c56: The test renderer's `drawFrame()` covers every batch applied before it. A key handler that read layout and then applied one more batch left a notify owed after the frame, and the next simulated input redrew the unchanged page: one extra painted frame and about 18M instructions per key in the mailbox bench proxy.
- d711914: `:focus-visible` after a script focus (`focus()`, `autoFocus`, `focusElement`) now follows Chrome. It used to inherit the visible state of the element focus left, plus "no input yet"; Chrome keeps two window-wide facts instead: a mouse press that moves focus marks it as the mouse's and clears the last key, a key down (Shift alone too, not Ctrl, Alt or Cmd) sets the key, and a script focus changes neither. So a script focus now shows the ring after a press on blank body, and after Tab then a click on blank body, and no longer shows it when a text field was script-focused after a click.
- 521b773: `:focus-visible` (`focusVisible` and `hasFocusVisible`) no longer depends on `transition`. An element with any `transition*` ignored the focus ring when a script focused it before a key was pressed (autofocus, a dialog's first focus, `focusElement`), and a text field focused by a click lost it too, because the transition path read the window's last input device instead of the focus state the element without a transition uses. A `focusVisible` style on a transitioned element now matches in the same cases as on a plain one, and still transitions in.
- c4b1800: A hover that gives an element a background it had none of is a patch frame: an element whose `hover` or `hasHover` sets a background colour paints a fully transparent background quad where it has none (gpui's new `Style::keep_transparent_background`), so the quad is in the root both ways and the hover writes a colour over it. The mailbox row of ghia-bench crosses at 4.48M instructions against 8.57M, all 18 crossings patched; the scroll phase pays the quad, 7.89M a tick against 7.64M. The page, the hit test and the pointer events are what they were.
- 0a746f2: A row of a `<virtual-list>` is patched where it was recorded: a hover that only paints (a background colour over a background the row already has) is drawn by writing the primitives of the two rows over the frame shown, and no longer by a frame built whole. In the mailbox proxy of ghia-bench with rows that paint a background, a row crossing costs 4.7M instructions against 9.7M (the bench app as it is, whose hover gives the row a background it did not have, adds a quad and is still a frame built whole: 9.3M). A row the list has put elsewhere since it was recorded is a frame built whole (`unpatchable["Hover:Relocated"]`), and the frame after a patch that moves the rows by a scroll is built whole too. The patch compares the operations of a root by their fields where it formatted them (25.7M of a 27.9M tick), and a marker a recording puts elsewhere is no difference.
- 4ee7fa6: A hover that only changes how an element paints is drawn by patching the frame shown: the roots that hold it (a row, a card, a small control) are built again and gpui writes the primitives they paint over the frame, where the whole page was built. The frame built whole leaves the roots that hold such a hover ready (`retained(..).patchable()` for a root of at most 64 elements that lifts nothing, has no group and no intrinsic size); the preview of a tick takes the hover from the elements the dispatcher left, and a hover on an element no root holds is a frame built whole (`unpatchable.Hover`). A hover that adds or takes away a primitive (a background where there was none), a group, and a hover a listener hears are frames built whole, as before.
- 57e782f: The scene kept for the next relocatable subtree (a row of a `<virtual-list>`) is cleared once the row's recording has been taken from it: it held the primitives of the last row, their path vertices and the pixel buffers of surfaces among them, alive until the next relocation.
- c4e29c2: An app that does not turn automation on no longer loads zod (about 1.8 MB of heap). `@ghia/native/runtime` imported the automation client, and with it zod and eventsource-parser, at the top; it now imports it when automation is enabled (stdin is not a TTY, or a browser render). `enableAutomation` and `installBrowserAutomation` return a promise for that reason, and in the browser `globalThis.gpuix` is set once the client has loaded instead of inside `render()`.
- d246bac: Lower memory. A CSS length is stored as one term (or a shared array for a mixed-unit `calc()`), so a style takes 6.3 KB instead of 16 KB; a Motion state's tracks are boxed; and an image tile over 512 px gets an atlas texture of its own size. At rest, with the Solid transform cache warm: the ghia-swiftui demo 131 to 116 MB, its Apple Music clone 260 to 211 MB, the fluid-functionalism gallery 195 to 178 MB (measured with a 256 KiB instance buffer start that was reverted afterwards: up to 5 MB less than a build now).
- 7419c3b: Input wakes JS once per event on macOS 26 and later. AppKit begins a Core Animation transaction for every event it sends, and its update cycle committed one that began before the display's next frame boundary from a timer at that boundary, which woke JS for a tick that did nothing else. The pump now commits it right after the event. Mouse moves over ghia-bench's Mailbox at 120 Hz: 1.03 to 1.09 wakes per move against 1.46 to 1.88, about 140 process wakeups a second against 185 to 230, and 4 to 12% fewer instructions per move.
- 134e72b: A window with native views no longer grows while it draws: the published addon kept a record of every composed frame (about 2.4 MB per 1000 frames on the Apple Music clone). The GPUI layers above a native view share the window's pipelines and command queue, keep two drawables instead of three, and hold none while they have nothing to draw. A transitioning element with no state style to fold no longer copies its style.
- 5a6ecc0: The hover of an element is classified as paint-only when its `hover`, `groupHover` or `hasHover` style changes nothing but colours, an opacity that stays a layer, or the colour of a shadow or a border. Nothing is drawn differently yet: the classification (`events/hover_paint.rs`) is what the hover patch frames that follow are built on.
- fe4feb4: A hover that only changes how elements paint (a background colour, a border colour, the colour of a shadow) asks the window for a tick instead of rebuilding the view. A patch frame takes the tick when it can; when it cannot, or when patching is off, the frame is built whole in the same draw and shows the same page as before. A hover that a listener hears (`pointerenter`, `mouseover`, ...) or that changes anything else is a frame built whole, as it was.
- 05929b1: A patched tick whose changed operations keep their kind and bounds (a colour loop, a caret blink, a stroke that moves inside its box) writes their primitives over their slots in the scene's typed vectors, instead of replaying the whole frame's operations and sorting every vector again: several million instructions on a 2700 operation frame, whatever the number of operations that changed. The first patch after a frame built whole still makes the scene again, and so does a patch that moves a primitive, clips one away or changes an operation that is not a plain primitive. `getPatchCounters()` has `sceneRebuilds` and `inPlacePrimitives` for it.
- 4944439: Putting the operations of a recording back into the scene (the replay of a retained row, a scroll translate, and the scene made again from its log after a patch) copies each primitive twice and no more, and works out its window bounds once. It used to clone it for the log, move it through `insert`, `record` and `route`, and clone it again for the typed vector (about eight copies of the 240 bytes of a glyph sprite). In the mailbox scroll proxy a frame replays about 2700 operations, and a tick went from 12.4M to 9.8M instructions.
- c0e1eb7: A primitive of a recording that is put in the frame (a row built before it is shown, a row moved by a scroll translate) is copied once into the slot the log keeps it in and moved there, and no longer through a temporary and several moves: the 328 patched ticks of the mailbox scroll proxy cost 3.60M instructions against 4.08M, the ticks built whole 11.99M against 12.26M.
- 1ed2c72: A frame patched by a scroll translate or by a patch whose operations moved makes its scene again from the log it already has and no longer copies every primitive into a second log: the 328 patched ticks of the mailbox scroll proxy cost 4.09M instructions against 5.07M, and the scroll mean 8.54M against 9.06M.
- fcc0d2e: The scene a relocatable row is recorded in is kept for the next row, with the room its vectors grew to, instead of being made from nothing and grown by doubling in every frame that builds a row.
- cef50f9: The scene sorts its sprites by draw order and atlas texture, stably, and moves each primitive once instead of sorting the primitives themselves: a frame of 2000 glyphs spent a sixth of a rebuild in that sort. Sprites of one order never overlap, so which is drawn first is not seen, and the renderer batches by texture as before. Owner-approved engine change (docs/fork/syncing-upstream.md).
- b871632: The primitives of a frame are sorted by draw order and atlas texture as one number each instead of a tuple of structs: the 328 patched ticks of the mailbox scroll proxy cost 3.26M instructions against 3.60M, the ticks built whole 11.61M against 11.99M, the hover row crossings 8.60M against 9.12M.
- c6a6271: The primitives of a frame are sorted by a sort that finds the sorted runs they come in (a row of a list at a time) and merges them: the 328 patched ticks of the mailbox scroll proxy cost 3.12M instructions against 3.26M, the ticks built whole 11.37M against 11.55M.
- 4e79714: `getPatchCounters().scrollPatch` says how the frames drawn after a wheel event over a `<virtual-list>` would have been drawn by moving the rows of the frame shown instead of building the page: `frames`, `eligible`, `mispredicted`, `hoverOnly` and `reasons` (the first reason a frame was not a translate: `Edited`, `Membership`, `Hover`, `Place`, `Region`, `Clip`, `Focus`, `A11y`, `ScrollAnimation`, `NotRelocatable`, `Other`). Every frame is still drawn whole and nothing paints differently; the first step of drawing a list scroll without the page. `GPUIX_SCROLL_PATCH_OFF=1` (or `setScrollPatchEnabled(false)` on the test renderer) turns the bookkeeping off.
- 69e9c2b: A wheel event over a `<virtual-list>` in the draw of a tick is drawn whole: a translate builds nothing, so it took the tick (a CSS transition, a keyframe animation, a motion value, the blink of a caret) and nothing asked for the next frame, and what followed the clock stood still until a frame was built whole. The frame is `Clock` in `getPatchCounters().scrollPatch.reasons`, for a tick requested for the draw or a last frame that asked for another, and the translates resume when nothing runs.
- 671330d: `getPatchCounters().scrollPatch` counts the frames after a wheel event over a `<virtual-list>` that could be a translate of the rows by what would change on screen, not by the hitboxes under the pointer: `Hover` is a pointer whose move from one element to another would restyle something (`hover`, a group, `whileHover`, `:has(:hover)`) or reach a listener (`pointerenter`, `pointerleave`, `pointerover`, `pointerout` and the mouse ones, also on `window`), and `HitboxChain` (in `held` only) counts the hitboxes that change under it. A root nested in a row that was built is no `NotRelocatable` run any more, and `held` names the edge a recording leaves bare (`Region.top`, `Region.bottom`, `Region.side`) and why a row cannot be moved (`NotRelocatable.noRun`, `.noRecording`, `.unmovable`). In the mailbox proxy 328 of 720 frames are eligible and none mispredicted (none before). Every frame is still drawn whole.
- 3ed3d47: An `IntersectionObserver` (and `onLayout`, `ResizeObserver` and `content-visibility: auto`, which read the same boxes) is swept after the frames that move the rows of a `<virtual-list>` in place, as after a frame that built them: the sweep was a canvas that only a painted frame runs, so a row that a translated frame brought into view was not told of until a frame was built whole.
- c642e6a: The tick that follows a frame that moved the rows of a `<virtual-list>` in place (the blink of a caret, a transition) is a patch again: the translate left the view the scroll had notified on the queue, so the tick declined for a pending view and was drawn whole.
- 523e8dd: The frame drawn after a wheel event over a `<virtual-list>` is built whole when a source other than the scroll differs from the frame shown (a press that restyles with `:active`, the focus, a selection, a measurement, a link, a command, a custom element): they notify the view with the entity the list notifies with, so the tree and the queue of views could not tell them apart and the translate left them out of the picture until the next frame built whole. The gate compares the sources as a tick does and says `Edited` (`getPatchCounters().scrollPatch.reasons`).
- bd73d27: The thumb of the scrollbar of a `<virtual-list>` is moved back by a translate that returns the rows to where the last whole frame painted it: the translate compared the new place of the thumb with the whole frame's and left a thumb that an earlier translate had moved on its other pixel.
- a0b62db: The frame drawn after a wheel event over a `<virtual-list>` with the scrollbar the system draws is no longer built either: the translate moves the thumb with the rows (the list's bar tells gpui, through `Window::paint_scroll_thumb`, how a scroll moves its thumb, and the quad is written over the operation it painted, at the bounds the build would paint it at), and starts the second of the bar's hold again as a built frame does. Where the thumb cannot be put there, the frame is drawn whole and says why: `Thumb.size`, `Thumb.alpha`, `Thumb.appear` (the first wheel after the bar faded) and `Thumb.track` in `getPatchCounters().scrollPatch.held`, and `applyDeclines.Thumb`. A frame that moves the rows is also drawn whole when the bar of a scroll container is due a frame (the end of its hold). The mailbox proxy with its default scrollbar patches 328 of 720 frames, as with `scrollbarWidth: "none"`, where it patched none.
- a198da5: The frame drawn after a wheel event over a `<virtual-list>` is not built when the rows only moved: the classifier's translates are drawn by putting the rows of the frame shown where a replay of their recordings puts them at the new position (the scene, the hitboxes, the boxes `getBoundingClientRect` reads, the regions text is selected from), the scene is made again from its log, the hover is followed as after a drawn frame, and nothing else is walked. `getPatchCounters().scrollPatch` gains `patched` and `applyDeclines` (why a translate that could be made was drawn whole; nothing is written before it declines), and a list with a scrollbar is a `Thumb` reason (the translate does not paint the thumb yet; `scrollbarWidth: "none"` has none). `GPUIX_SCROLL_PATCH_OFF=1` or `setScrollPatchEnabled(false)` draws every frame whole as before; under `GPUIX_RETAIN_VERIFY=1` each translate is compared with the frame built whole after it (scene with draw orders, hitboxes, registries).
- 863db25: A scroll translate writes the translated operations of each row straight into their places in the frame instead of collecting those of every row into vectors and copying them over, and a translate that declines still writes nothing. In the mailbox scroll proxy a patched tick went from 6.4M to 5.4M instructions.
- ec13354: A scroll write (`scrollTo`, `scrollTop = n`, `scrollLeft = n`) no longer lays the page out. It used to read the scroll metrics first and then draw a pending change, so a write after a mutation was a whole layout pass and the frame after it drew the page again (4 passes an ArrowDown and 2 a typed key in a mail client with a search box, 12 to 17 million instructions each). A write made while the layout is older than the tree is recorded and made by the layout that comes next, which clamps it, as a browser does; one with nothing pending clamps at once, as before. A `div` scroller written to another vertical position than the start while the layout is behind still lays out first, as scroll anchoring needs the DOM's order. `scrollTo({ top })` names one axis to native, which keeps the other. A read (`scrollTop`, `scrollHeight`, `clientHeight`) lays out only when a layout-class change is pending, so a write followed by a read still returns the clamped value. A smooth scroll and a write to a scroller mounted since the last render lay out first too.
- 439271f: The overlay scrollbar asks for no frame while it holds. After a scroll the bar stays whole for a second and then fades over 200 ms; the second used to request a frame at every vsync that painted the same bar and made every tick unpatchable (one `scrollTo` was 70 to 140 frames built whole, most of the cost of an ArrowDown through a list). One timer on the window's clock now waits for the end of the hold and only the fade asks for frames. A bar under the pointer or a held thumb asks for none while it is steady either, and a tick (a caret blink) in the hold is a patched frame, as is the blink of an input beside a list that was scrolled. A tick that finds a bar painted at an alpha the clock has since changed is still drawn whole.
  
  A virtual-list row that the pointer had been over no longer keeps the page from patching: its hover left it in the set of elements no build had entered, so every blink beside a list under the pointer was a whole frame.
- 9bce77d: A node Solid removes is out of the native tree at once, as `removeChild` takes it out of the document, and a layout read in the same turn no longer lays out the removed subtree. The host used to detach it on the JS side and tell native only at the flush, so `getBoundingClientRect` or `scrollHeight` right after a keyed `<Show>` swap built and laid out the old subtree beside the new one (the mailbox navigate proxy: a detail scroller with twice its children in the pass, 56 elements built there for 40 now). `removeHostNode` now queues a new `detachChild` op, which takes the element out of its parent and keeps it, with its state, for an insertion that puts it back; the element is still destroyed at the flush if it stayed out.
- f6b9458: Solid no longer queues a `setStyle` or `setCustomProp` for a value the element already has. An effect that ran again and built an equal style object (a row whose style reads `selected`, an `aria-label` and a style in one effect) sent the whole style to native every time: in the bench's mailbox app, 180 identical `setStyle` ops and 27 KB of JSON for a key that changed nothing. The host remembers the JSON it last wrote for each element's style and custom props and writes only what differs from it, so a style object changed in place and passed again is still written, and so is a key order that differs. A prop never written is written, and a new native element starts with nothing written. `@ghia/native/host` exports `SentWrites`.
- 77be0bf: The test renderer has `captureShownFrame(path)`, which saves the frame that was drawn last as it is: `captureScreenshot` notifies the view and refreshes the window first, so it could only show a frame built whole, never what a patched tick or a frame that moved the rows of a `<virtual-list>` in place drew.
- 4b90976: Fixes taken from upstream GPUI. A window with `windowBackground: 'blurred'` is blurred on macOS 27 again. Translucent layers composite with the right alpha over a transparent target: two half-transparent boxes that overlap no longer add up to an opaque one. A cached view follows a change of the opacity it inherits and keeps its subscriptions to the entities it read when it is reused. The cursor no longer reverts when a drag starts, because it is resolved after the listeners of every mouse event. A synthetic drag stops after the button is released. The menu key equivalents of backspace and delete show their glyphs. Two panics are gone, one for a released atlas texture and one for a hit test past the end of a wrapped line. The accessibility adapter is released when its window closes, and the text system no longer leaks.
- c668d7f: A windowed `<virtual-list>` whose `itemCount` goes down keeps its list state: the heights measured so far, the scroll position and the focus handles stay, and only the rows at the tail are dropped, so the rows in view are no longer measured and laid out again on every change, and the work is as large as the drop and not as the count. A count that goes up still makes a new state, because gpui gives a spliced-in row no height hint (see `list_resize.rs`). A rebuild also skips a pass over every row that made no change.
- 8d9a70f: The rows of a virtual list are retained: a row that did not change is skipped and one the list scrolls by is moved, where every frame built every visible row. Only the changed row and the list around it are built. In the mailbox bench proxy a key (ArrowDown in a 10 000-message list) takes 52M instructions instead of 63M and builds 125 elements instead of 259; a chat page of `retain.perf` skips 92% of its elements at idle instead of 59%.
- dec3bf7: `onVisibleRange` of a `<virtual-list>` fires when the visible range changes, not on every scroll event. A scroll that stays within the same rows (a 30 px wheel tick over 72 px rows) reported the same `startIndex` and `endIndex` again, a native-to-JS event and a handler call for nothing; the list now keeps the range it last reported and reports a different one. The first scroll still reports its range, and `scrollToItem` still reports its own.
- a0d537f: The window title is given to the platform window when it changes, not on every frame. `GpuixView::render` called `Window::set_window_title` each time, which on macOS is an AppKit `setTitle` and an accessibility update per painted frame of a scroll. The view now keeps the title it last set and sets it again only when `setWindowTitle` (or the first render) gives it another.

## 0.11.1

### Patch Changes

- 52fd03d: A page with a `Reorder.Item` (a `layout` box with `dragOffset`) beside a looping animation patches the loop's ticks while nobody holds the item, as it does without the item. Until now every tick was drawn whole for as long as the item existed. While an item is held, its ticks are still whole frames.
- a2d57e7: A window opened with `GPUIX_BACKGROUND=1` in the environment emulates focus, as Chrome does with CDP's `Emulation.setFocusEmulationEnabled`: it behaves as active for `onFocus`, `onBlur`, `:focus-visible`, the caret and `focusElement`, without becoming the key window or activating the app. Until now a window opened behind other apps (`focus: false`) fired no focus event and drew no caret while typed text still arrived. A window without the variable is unchanged: a window that is not active fires no focus events, as in Chrome, and they fire once it is activated. The library reads the variable once, when the window opens; apps that map it to `focus: false` keep doing that.
- d70feb5: A blurred `box-shadow` on a box under an `opacity`, `filter` or `mask` ancestor is no longer cut off at a hard rectangle while the ancestor animates or holds its effect. The group's bounds and the draw order now count the whole blur: an outer shadow reaches three times its blur radius past its box, as it is drawn. The shadow paints as the same shadow with no ancestor effect.
- 05f72cd: `dragBy`, `dragTo` and `mouse.drag` drive a drag on a live window when the app drives its own renderer in-process (`connectTest(liveRendererAsTest(renderer))`). The live renderer delivers a press and a release to the page at once but a move only on a later turn of the event loop, so a drag stepped in one synchronous burst reached the page as press, release, then the moves, and a handle that ends its drag on `pointerup` never moved. `liveRendererAsTest` now waits one event-loop turn after every input it simulates, and `TestAutomationRenderer`'s input methods may return a promise.
- 7da4cea: `<nativeview>`: `onAttach` now runs inside the frame that makes the surface (in its prepaint), with a content view that already has the size of the element's padding box, instead of one event-queue turn after the frame. The view a library adds there is in its container when the frame places it, and the frame presents the view and the GPUI content around it with one Core Animation transaction, so a new glass view no longer shows for a frame before or after the content above it. Like `onDetach`, `onAttach` can no longer call gpuix (a renderer call from it fails with the nested-call error) and the state it writes is a later batch: children that wait for `onAttach` show a frame after the view, so a library should render them from the first frame. Where native cannot call JS from inside a frame, `attach` is still queued.
- bb3412f: A `<nativeview>` under an ancestor with `opacity`, `filter`, `mask` or `clip-path` now fades with the ancestor and keeps its children above it: the ancestor's effect group is split at the view, so the box is composited below the view and the children above it. The view takes the product of the opacities of the groups around it, a filter group's included.
- 6a78fe8: `kind: 'panel'` in the window options opens the window as a non-activating panel: a normal window (titlebar, resizing, buttons, appearance, background, normal window level) that can be the key window without activating the app. With `focus: true` it is key while the frontmost app stays frontmost, so a capture can show the key look (glass tints, accent colours, traffic lights) that a `focus: false` window never has. `renderer.isWindowKey()` reads whether AppKit reports the window as key. An unknown `kind` throws; `'normal'` is the default, and on Windows and Linux a panel is a normal window. A panel takes the keyboard like any key window, so open one only for a capture and close it right after.
- a6de850: A page that moves every root in each frame without a scroller doing it (a pan whose offset is a style) no longer pays for skipping roots it cannot replay. Retention judges each frame by what gpui replayed and what it had to build late, and while skipping loses it records and skips only a sample of the roots, coming back as soon as the sample replays again. The timeline pan with culling on costs 16 ms a frame instead of 21.5 (14.4 with retention off), and 243 ms instead of 400 with culling off. Pages whose frames replay well are unchanged. `GPUIX_RETAIN_GATE_OFF=1` turns the gate off, to time a run without it.
- ff5975c: An app with a `<webview>` no longer wakes JS 4 times a second at rest: WebKit's own wake-ups of the main run loop reach JS (2 to 5 wakes in 15 s at rest instead of about 63), and the events of a load, a page-set title and the result of `executeJavaScript` arrive in 1 to 9 ms instead of 5 to 75 ms. On a macOS version whose `CoreFoundation` is not the one this was checked against, the 250 ms timer is used as before.
